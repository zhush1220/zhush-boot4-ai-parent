# 数据权限使用指南

> 模块:`zhush-spring-boot-starter-biz-data-permission`(框架层) + `zhush-module-system`(业务实现层)
>
> 能力:**行级权限**(SQL 自动追加过滤条件)+ **字段级权限**(响应字段置空/脱敏),支持五级自由启停。

---

## 一、功能总览

| 能力 | 实现方式 | 生效位置 |
| --- | --- | --- |
| 行级权限 | `@DataPermission` 注解 + MyBatis-Flex 方言 `prepareAuth` 钩子,按当前用户数据范围自动追加 `WHERE` 条件 | SELECT / UPDATE / DELETE(仅走 QueryWrapper 的 SQL) |
| 字段级权限 | `@FieldPermission` 注解 + `ResponseBodyAdvice`,无权限时字段置空(CLEAR)或脱敏(MASK) | 接口响应序列化前 |

数据范围类型(对应 `sys_role.data_scope`):

| 值 | 含义 | 追加的过滤条件 |
| --- | --- | --- |
| 1 | 全部 | 不过滤 |
| 2 | 本部门 | `dept_id IN (本部门)` |
| 3 | 本部门及以下 | `dept_id IN (本部门 + 全部子孙部门)` |
| 4 | 仅本人 | `create_by = 当前用户ID` |
| 5 | 自定义 | `dept_id IN (角色配置的部门ID集合)` |

多角色时取**并集**;部门集合为空时自动退化为"仅本人";未登录(定时任务等)不过滤。

## 二、启用与配置(五级启停)

### 1. 配置开关(application-dev.yaml)

```yaml
zhush:
  data-permission:
    enabled: true        # 总开关,默认 false(不启用,零开销)
    row-enabled: true    # 行级权限子开关,默认 true(受总开关约束)
    field-enabled: true  # 字段级权限子开关,默认 true(受总开关约束)
```

### 2. 五级控制粒度

| 级别 | 方式 | 说明 |
| --- | --- | --- |
| 1 全局 | `zhush.data-permission.enabled` | `false` 时所有相关 Bean 不注册,零侵入 |
| 2 分类 | `row-enabled` / `field-enabled` | 单独关闭行级或字段级 |
| 3 注解 | `@DataPermission(enabled = false)` | 方法级覆盖类级注解,临时关闭 |
| 4 代码 | `DataPermissionHelper.ignore(...)` | 方法内某段逻辑跳过过滤 |
| 5 默认 | 不标注 `@DataPermission` | 未标注的方法完全不过滤 |

### 3. 模块接入(pom)

```xml
<dependency>
    <groupId>com.zhush</groupId>
    <artifactId>zhush-spring-boot-starter-biz-data-permission</artifactId>
</dependency>
```

`zhush-server` 与 `zhush-module-system` 已接入。

### 4. 数据库脚本

启用前需先执行 `sql/04_dept_data_scope.sql`:

- 新建 `sys_dept` 部门表(含根部门初始数据)
- `sys_role` 增加 `data_scope_dept_ids` 列(自定义范围的部门ID,逗号分隔)
- 业务表需有部门/用户归属列(默认 `dept_id`、`create_by`,可通过注解属性调整)

## 三、行级权限使用

### 1. 基本用法

标注在 **Service 方法或类**上(也支持 Controller):

```java
// 方法级:该方法执行期间所有走 QueryWrapper 的 SQL 自动过滤
@DataPermission
public PageResult<OrderVO> getOrderPage(OrderQuery query) {
    return orderMapper.selectPageX(query, queryWrapper);
}

// 类级:整个 Service 生效,个别方法可关闭
@Service
@DataPermission
public class OrderService {

    @DataPermission(enabled = false)  // 该方法不过滤
    public OrderStatisticsVO statistics() { ... }
}
```

### 2. 自定义归属列名

表结构与默认列名不一致时:

```java
@DataPermission(deptColumn = "org_id", userColumn = "owner_id")
public List<ProjectVO> listProjects(ProjectQuery query) { ... }
```

### 3. 临时跳过过滤

`@DataPermission` 方法内部需查全量数据(统计、内部校验)时:

```java
@DataPermission
public OrderDetailVO getOrder(Long id) {
    OrderVO order = ...; // 已过滤

    // 这段查询不过滤
    long total = DataPermissionHelper.ignore(() -> orderMapper.selectCountByQuery(qw));
    ...
}
```

### 4. 生效边界(重要)

- **仅拦截走 QueryWrapper 构建的 SQL**(`selectListByQuery`、`selectPageX`、`update(entity)` 等);XML 原生 SQL、`selectOneById` 等不经过 `prepareAuth` 的调用**不会过滤**
- INSERT 不过滤
- 需要过滤的表必须有对应的归属列,否则 SQL 报"列不存在"错误
- 数据范围为"仅本人"但用户ID缺失时,追加 `= -1` 条件(拒绝所有数据,安全兜底)

## 四、字段级权限使用

### 1. 基本用法

标注在**响应 VO 的字段**上,`value` 为权限标识(与菜单权限体系一致,由 Sa-Token 判定):

```java
@Data
public class AdminUserVO {

    /** 无权限者返回 null */
    @FieldPermission("system:admin-user:id-card")
    @Schema(description = "身份证号")
    private String idCard;

    /** 无权限者返回 *** */
    @FieldPermission(value = "system:admin-user:mobile",
                     strategy = FieldPermission.Strategy.MASK)
    @Schema(description = "手机号")
    private String mobile;

    /** 自定义脱敏占位 */
    @FieldPermission(value = "system:admin-user:salary",
                     strategy = FieldPermission.Strategy.MASK,
                     maskValue = "保密")
    @Schema(description = "薪资说明")
    private String salaryRemark;
}
```

### 2. 处理策略

| 策略 | 行为 |
| --- | --- |
| `CLEAR`(默认) | 字段输出 `null` |
| `MASK` | String 字段输出 `maskValue`(默认 `***`);非 String 字段等同置空 |

### 3. 生效边界

- 自动拆包 `Result` / `PageResult` / 集合 / 嵌套 VO(最大递归深度 4 层)
- 基本类型(`int` 等)字段无法置空,会跳过并打告警日志——**需要权限控制的字段请用包装类型**
- 处理失败仅记录 warn 日志,不影响接口正常返回
- 给菜单表配置对应权限标识(如 `system:admin-user:mobile`)并分配给角色,即可控制"谁能看到该字段"

## 五、业务侧实现(system 模块)

框架通过两个 SPI 与业务解耦,system 模块已提供管理端实现(`com.zhush.system.security` 包):

### 1. AdminDataScopeProvider(数据范围解析)

解析流程:

```
未登录 ────────────────────────────→ 全部(不过滤)
   │
登录 → 查启用角色(sys_admin_user_role → sys_role)
   ├─ 无启用角色 ───────────────────→ 仅本人(最小权限)
   ├─ 超管(super_admin)/任一角色范围=1/未配置 → 全部
   ├─ 含部门类角色(2/3/5)→ 并集部门ID → dept_id IN (...)
   │    · 2:本人 deptId
   │    · 3:本人 deptId + 子孙部门(内存 BFS 展开)
   │    · 5:解析角色 data_scope_dept_ids
   └─ 全部角色均为 4 ────────────────→ 仅本人
```

- 解析结果按用户缓存 **60 秒**(每条 SQL 都会触发解析),角色数据范围调整后**最迟 1 分钟生效**
- 方言层调用 Provider 时已抑制递归,Provider 内部查库不会死循环

### 2. AdminPermissionChecker(字段权限判定)

委托 `StpAdminUtil.hasPermission(permission)`,未登录一律视为无权限。

> 两者均为 `@Component`,自动替换 starter 的默认实现(默认实现为"全放行")。会员端如需数据权限,可参照实现基于 `StpMemberUtil` 的 Provider/Checker。

## 六、角色数据范围配置

### 1. 配置接口

```
PUT /admin/system/role/assign-data-scope     权限标识:system:role:assign-data-scope
```

请求体:

```json
{
  "roleId": 2,
  "dataScope": 5,
  "dataScopeDeptIds": [10, 11, 12]
}
```

- `dataScope` 取值 1-5;仅为 5(自定义)时保存 `dataScopeDeptIds`,其余类型自动清空
- 角色详情/分页(`AdminRoleVO`)返回 `dataScope` 与 `dataScopeDeptIds`(逗号分隔字符串)

### 2. 部门管理接口

```
POST   /admin/system/dept          新增部门     system:dept:create
PUT    /admin/system/dept          修改部门     system:dept:update
DELETE /admin/system/dept/{id}     删除部门     system:dept:delete
GET    /admin/system/dept/{id}     部门详情     system:dept:query
GET    /admin/system/dept/list     部门列表     system:dept:query
GET    /admin/system/dept/tree     部门树       system:dept:query
```

约束:删除时不能存在子部门/部门下用户;父级不能设置为自身或其子孙部门;管理员通过 `sys_admin_user.dept_id` 归属部门。

## 七、常见问题(FAQ)

**Q1:开启后接口报"Unknown column 'dept_id'"?**
标注了 `@DataPermission` 的方法查询的表没有默认归属列。用注解属性指定实际列名,或该方法不加注解。

**Q2:为什么某个查询没有被过滤?**
依次检查:① 总开关/row-enabled 是否开启;② 方法或类上是否标注 `@DataPermission`;③ SQL 是否走 QueryWrapper(XML 原生 SQL 不拦截);④ 是否在 `DataPermissionHelper.ignore` 上下文中。

**Q3:调整了角色数据范围但没生效?**
Provider 结果按用户缓存 60 秒,等待 1 分钟或重启服务。

**Q4:`@FieldPermission` 加在 `int` 字段上不生效?**
基本类型无法置空,改用包装类型(`Integer`/`Long` 等)。

**Q5:超级管理员会被过滤吗?**
不会。`super_admin` 角色编码或任一角色数据范围为"全部"时直接放行;角色 `data_scope` 为 NULL(存量数据)也视为全部。

**Q6:如何完全关闭数据权限?**
`zhush.data-permission.enabled: false`(默认值)。关闭后相关 Bean 不注册,无任何运行时开销。
