# 对话框自然语言多能力任务实现方案（文案 · Word · PDF · 视频 · 图片）

> 需求：在 AI 智能助手对话框中，用户用自然语言表达任务意图（如「把这段介绍写成文案」「根据这些内容生成一个产品视频」「将结果导出为 Word/PDF」「解析这份 PDF 并总结」），系统自动选择对应的大模型/工具完成任务并产出结果（文本或文件）。
> 定位：**方案文档，暂不改动代码**。结论基于当前代码勘查 + AgentScope 2.0.2 实际能力。
> **状态更新（2026-09-23）**：P0-P2（文案 / Word / PDF / 文档解析）已按本方案落地，P3-P5 未开工。逐项对账见 [第十一节](#十一实现进度对账2026-09-23代码核实)；第一至第十节为立项时的原始判断，保留不改。全局现状另见 [analysis/05-AI智能功能全面分析](../analysis/05-AI智能功能全面分析.md)。
> 关联：《Token计量与审批续跑深化方案.md》《AgentScope2.0整合方案.md》《文档解析使用指南.md》《AI 模型与敏感词动态化设计方案 v2》。

## 一、需求解读

拆成三个可独立演进的能力：

1. **意图路由**：一句自然语言 → 判断要做的任务类型（文案 / 图片 / 视频 / Word / PDF / 文档解析 / 纯问答）。
2. **能力编排**：按任务类型选择正确的「执行者」——可能是对话大模型本身、专门的生成模型、或确定性渲染/解析工具。
3. **产物交付**：文本直接回气泡；文件（docx/pdf/mp4/png）经文件服务落库、回传下载链接，前端渲染产物卡片。

### 2.2 缺失（本方案需补）

1. **文档「生成（输出）」能力**：全仓无 `XWPFDocument`(POI) / iText / PDFBox-生成 依赖——只能解析、不能把 AI 内容产出为 docx/pdf 文件。
2. **图像 / 视频「大模型生成」对接**：无 DashScope 文生图（wanx）/ 文生视频 SDK 或 HTTP 封装（`MultiModalConversation`/`ImageSynthesis` 全无）；agentscope 扩展仅 `model-dashscope/openai/ollama`（均 chat 模型），**不含多模态生成**。
3. **按 capability 的运行时模型路由**：`resolve(code)` 无「按能力选模型」入口。
4. **产物（附件）数据与前端渲染**：`ai_chat_message` 无 `attachments`；前端无下载卡片/视频播放器产物组件。
5. **多模态生成工具的入参约定与异步回推链路**。

## 三、核心架构判断（本方案的定盘星）

> **不要把图像/视频/文档生全都塞进对话 LLM 的 model 槽位。正确抽象是：对话模型（text 能力）=「编排大脑」，各类生成/渲染/解析能力 = 「工具（@AgentTool）」，由 ReAct 按自然语言意图自主调用。**

理由（均基于勘查事实）：

1. `HarnessAgent.Builder.model(...)` 只接受**单一 chat Model**；文生图/文生视频是**异步任务式 API**（提交→轮询→取 URL），并非 token 流式对话，不能复用 chat 循环。
2. 「文本 → Word/PDF」是**确定性排版**（POI/iText），不需要也不应该消耗大模型；大模型负责产出**结构化内容**，工具负责**渲染成文件**。
3. 「文案」本质就是 text 模型直接生成；区别只在用**哪个** text 模型 / 哪套 prompt——用 capability + prompt 模板路由即可，无需新框架。
4. AgentScope 的 `@AgentTool` 反射桥接已验证可用（union 选品等工具在跑），把「生成海报/视频/Word/PDF」做成工具，天然获得：LLM 自主调用、参数 schema、审计、审批门禁、Token 计量复用。

因此本方案是**「薄改造 + 工具增量 + 前端产物渲染」**，而非重构对话内核。

## 四、总体方案

### 4.1 自然语言意图路由（三级，可叠加）

- **L1 模型驱动（主推，零额外分类器）**：为 `ai-chat` 等 Agent 的 `system_prompt` 增加「能力说明 + 何时调用哪个工具」，工具 `description` 写清触发语义（如 `generateDocument`：「当用户要求导出 Word/PDF/文档文件时调用」）。ReAct 依据用户话语自主选择工具。契合现有 `maxSteps` 多轮推理。
- **L2 用户显式选择（强控制，前端已有下拉雏形）**：对话框增加「能力/模式」选择器（自动 / 文案 / 图片 / 视频 / Word / PDF / 解析）。选「视频」时：后端把该意图注入 prompt（强化），或路由到预绑定工具的专用 Agent 定义（`agent_definition` 新增 `name=ai-video` 等，`tool_names` 限定）。前端 `data.ts` 的分组下拉可复用。
- **L3 前置意图识别（可选增强）**：`stream()` 前用一个轻量分类（关键词规则 or 一次小模型 `callOnce` 分类）判定 `taskType`，用于埋点、配额、UI 预置占位。非必需，二期视准确率引入。

> 路由产物统一为一个 `taskType ∈ {chat, copywriting, image, video, docx, pdf, parse}` 上下文，供后续管线与前端渲染分支使用。

### 4.2 能力矩阵（任务 → 执行者 → 产物）

| taskType | 执行者 | 依赖模型/能力 | 产物 | 同步/异步 |
|---|---|---|---|---|
| chat | 对话 LLM | capability=text | 文本/Markdown | 流式 |
| copywriting 文案 | 对话 LLM（可指定更优 text 模型 + prompt 模板） | text | 文本（可再导出文件） | 流式 |
| image 图片/海报 | 工具 `generateImage` | capability=image（wanx 等） | png url | **异步任务** |
| video 视频 | 工具 `generateVideo` | capability=video（文生视频） | mp4 url | **异步任务**（耗时） |
| docx Word | 工具 `generateDocument(type=docx)` | 无（POI 渲染）；内容来自 LLM | docx url | 同步（秒级） |
| pdf | 工具 `generateDocument(type=pdf)` | 无（iText/OpenPDF 渲染）；内容来自 LLM | pdf url | 同步 |
| parse 解析文档 | 工具 `parseDocument` | 无（复用 `DocParseService`） | text/html + 交给 LLM 总结 | 同步 |

### 4.3 五类任务实现管线

**(a) 文案**：无需新模型。文案 = text 模型 + 专用 prompt。落地：`agent_definition` 增 `ai-copywriter`（`system_prompt`=文案方法论，`model` 指向 capability=text 的更优模型），或 `copywriting` 工具内按模板生成。前端「文案」模式即选该 Agent。

**(b) 图片 / 海报（异步）**：
- 新增 `@AgentTool generateImage(prompt, size, style...)`：内部按 `capability=image` 取模型配置（`apiKey/baseUrl`），调用 DashScope 文生图（wanx）**异步任务 API**；返回任务 id。
- 生成未完成时工具返回「已提交，生成中」+ 占位；由 **WebSocket / 轮询 / MQ 回调** 在完成后把图片 URL 经 `FileClient.upload`（转存自有存储，避免外链过期）落 `infra_file`，写入消息产物，并经会话通道推给前端。
- 与联盟本地海报模板（`image_config` 合成）并存：模板类走 union 既有能力，AI 生图走本工具。

**(c) 视频（异步，成本最高）**：
- `@AgentTool generateVideo(script, scenes, ratio...)`：调 DashScope 文生视频/图生视频异步任务；轮询完成后转存 `infra_file`，回推 mp4 URL。
- 必须异步化：提交即返回 `taskId`，避免阻塞 SSE；进度经 WebSocket 推送；产物卡片显示封面+播放。
- 强配额/审批：视频成本高，纳入计量与（会员）配额闸门，必要时审批。

**(d) Word / PDF（确定性渲染，关键补依赖）**：
- 管线：**LLM 产出结构化内容 → 工具渲染文件**。两种触发：
  1. LLM 直接在回答中产出 Markdown/结构化 JSON，前端「导出为 Word/PDF」按钮调 `POST /admin/ai/export`（走 `generateDocument` 同款渲染服务）。
  2. `@AgentTool generateDocument(contentMarkdown, format=docx|pdf, fileName)`：LLM 判断用户「要一个 Word 文件」时自主调用，工具把内容渲染为 docx/pdf 字节 → `FileClient.upload(bytes, name, contentType)` → 返回 `{url, fileName, size}` 作为工具结果，LLM 汇总并附产物。
- 渲染实现：Markdown/结构化 → POI `XWPFDocument`（docx）/ iText·OpenPDF（pdf）；标题/段落/列表/表格/图片（内容里的图片先解析成 URL 再嵌入）。**新增依赖见第七章**。

**(e) 文档解析（输入侧，复用）**：
- `@AgentTool parseDocument(fileUrl|fileId)`：内部复用 `DocParseService`/`FileParseUtils`（已支持 docx/pdf/pptx/xlsx，含内嵌图片）。解析出的 `text` 交回 LLM 做摘要/翻译/问答。
- 前端对话框增加**附件上传**：先 `POST /admin/system/file/upload`（或 `parse-doc`）拿 `fileId/url`，随消息发给 agent；agent 据「解析这个 pdf」话语调用 `parseDocument` 工具。

### 4.4 按 capability 的模型路由（starter 薄改造）

- `AgentModelResolver` 增 `Optional<ModelConfig> resolveByCapability(String capability)`（遍历 cache 过滤 `capability` 且启用，按 `priority` 取最优；可含回退 yaml）。
- 生成类工具不建 chat Model，而是从 `ModelConfig`（`type/baseUrl/apiKey/model`）拿**调用凭证**，用 DashScope 官方 SDK / HTTP 调生成 API。这样图像/视频模型仍统一在 `ai_model` 表管理（启停/默认/优先级/加密 Key/动态刷新全部复用）。
- `ModelConfig`/`ai_model` 的 `capability` 语义扩展可选子类型（如 image 的 `t2i`、video 的 `t2v/i2v`）：放入现有 `options` JSON，避免加列。

### 4.5 产物文件流转

- 所有生成文件统一 `FileClient.upload(byte[], fileName, contentType)` → 落 `infra_file` → 返回 `url/path`（多存储、外链、删除管理已有）。
- 大文件/慢生成（视频）：**转存后回链**，不把二进制塞进 SSE。
- 消息与附件关联：见 4.7。

### 4.6 异步任务与进度回推

- 图像/视频用现有异步设施（quartz 任务表 / MQ / WebSocket）。建议：工具提交 `taskId` → 写 `agent_async_task`（新增轻量表：taskId/sessionId/messageId/type/status/url/errorMsg）→ 定时或回调拉取供应商任务状态 → 完成转存 + 更新消息产物 + **WebSocket 推 `{sessionId, messageId, artifact}`** → 前端该气泡由「生成中」切换为产物卡片。
- 会话状态复用 `ai_chat_session.status`（已有 `3-审批挂起`，可扩展 `5-生成中`）。

### 4.7 数据模型扩展

- `ai_chat_message` 增 `attachments JSON NULL`（`[{type:image|video|file, url, name, size, coverUrl?, taskId?}]`）；或复用现有 `tool_calls` JSON 内嵌产物 URL。二选一，建议独立 `attachments` 便于前端直接渲染。
- `AiChatMessageVO`/前端 `AiChatMessageVO` 同步透传 `attachments`。
- 新增 `agent_async_task`（图像/视频异步任务态）。
- `agent_definition` 视需要新增专用 Agent（`ai-copywriter`/`ai-image`/`ai-doc`）并配 `tool_names`；或统一 `ai-chat` 挂全工具靠 prompt 分流。
- 菜单/权限：生成能力可复用 `ai:assistant`，或按 `taskType` 细粒度授权。

### 4.8 前端对话改造（`views/ai/assistant`）

- **输入区**：加附件上传（复用 `requestClient` FormData 上传，图片/文档）+「能力模式」选择器（下拉，复用 `data.ts`）。
- **消息类型**：`use-chat-stream` 的 `ChatMessage` 增 `attachments?`、`taskType?`；新增产物事件解析（工具结果/WebSocket 推送回填）。
- **渲染**：`message-bubble.vue` 增「产物区」——图片预览、视频 `<video controls>`、文件下载卡片（图标+名+大小+下载按钮，走 `requestClient.download` Blob 或直链）；「生成中」占位（复用 `Spin`）。
- 已有 `tool-call-card.vue` 展示工具调用，产物可挂其下或独立区。

## 五、与既有能力的复用关系

- **Token 计量**：图像/视频/文本调用均产生用量，直接接入《Token计量与审批续跑深化方案》的 `agent_token_usage`（建议扩展 `type` 维度或按 model 定价）。生成任务按次/按量计费。
- **审批/敏感词**：`generateImage/Video/Document` 标注敏感或命中敏感词 → 走审批门禁（人脸、品牌、合规文案），复用分级。
- **审计**：工具调用已落 `agent_audit_log`，产物 URL 记入 `tool_result`。
- **文档解析 / 文件服务 / Excel**：解析与导出直接复用，不重造。
- **多模型动态池**：image/video/text 模型统一 `ai_model` 管理，启停/加密/刷新/默认全复用。
- **union 模板**：联盟「AI 文案/海报」入口可与本对话能力打通（对话产文案→一键海报模板）。

## 六、安全、成本、配额

1. **成本闸门**：图像/视频单价高，先做**同步计量 + 配额上限**（会员日/月额度、租户预算），超限拒绝并提示。
2. **内容合规**：生成前入参、生成后可选产物再过敏感词；涉政/涉黄/品牌走审批或拦截。
3. **文件安全**：上传类型白名单、大小上限（已有 `zhush.file.max-size`）；解析不可信文档的沙箱/超时；产物外链鉴权与时效。
4. **越权与隔离**：工具执行携带 `AgentContext`（userId/tenantId），产物按会话/租户隔离，禁止跨用户读取附件 URL 猜测。
5. **异步任务安全**：`taskId` 与 sessionId 绑定，回调校验，防伪造完成。

## 九、风险与注意事项

1. **多模态 ≠ 对话模型**：切勿把 wanx/文生视频当作 `HarnessAgent.model`；坚持「能力=工具」，否则对话内核会被异步/非流式语义拖垮。
2. **异步链路复杂度**：图像/视频引入任务表、轮询/回调、断线重连；需幂等与超时回收，避免悬挂任务与重复转存。
3. **ReAct 选错工具**：工具过多时 LLM 误调用概率上升——用 L2 显式模式收敛候选集、精炼工具 description、限制 `maxSteps`。
4. **PDF 中文与许可**：字体内嵌与 iText 许可证需提前确认；优先 OpenPDF/Apache 许可栈。
5. **文件生命周期**：产物长期存储成本与清理策略（过期删除 `infra_file`）；外链鉴权防泄漏。
6. **成本失控**：视频/图像按量计费，务必 P4 前落地配额与计量，否则有预算风险。
7. **大文档解析**：Tika 有 10 万字符上限，超大文档需分段/截断策略喂给 LLM。

---

## 十、结论

1. **可行性高、改动可控**：AgentScope 工具机制 + 动态模型池 + 文档解析 + 文件服务 + 异步设施均已就绪；缺的只是「生成类工具」「文档输出渲染依赖」「capability 路由」「产物渲染」四块增量。
2. **核心思想一句话**：让对话大模型当调度大脑，把「文案/图/视频/Word/PDF/解析」做成一组 `@AgentTool`，按自然语言意图自主调用，产物经文件服务回链、前端渲染卡片；图像/视频走异步。
3. **落地节奏**：先文本域（P0-P2，快、稳、省），再多模态生成（P3-P4，配好计量与配额再上）。
4. 与 Token 计量、审批、敏感词、union 模板天然复用，形成「对话即生产（内容+文件）」的统一入口。
