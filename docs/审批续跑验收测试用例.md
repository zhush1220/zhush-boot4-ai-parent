# 审批续跑（路线 B）验收测试用例

> 配套《Token计量与审批续跑深化方案.md》4.8 节 S1–S5 落地。
> 目标：为「敏感工具审批 → 跨请求续跑」链路提供**可直接执行**的验收测试，覆盖自动化单测与需真实环境的集成用例。

## 0. 测试分层与边界

| 层次 | 范围 | 能否在本仓库自动化 | 交付物 |
| --- | --- | --- | --- |
| L1 单元 | 会话来源位灰度、续跑通道收发、审批降级判定依据、审批分支/幂等 | ✅ 可（无 DB/Redis/模型） | `src/test` 下 19 个用例 |
| L2 装配 | 配置开关 → Bean 条件装配（AgentStateStore/ResumeChannels） | ⚠️ 部分（需 Spring 上下文，模型可 Mock） | 见 TC-CTX-* |
| L3 集成 | SSE 跨请求续跑、`ConfirmResult` 喂回语义、真实 Redis 状态存储 | ❌ 否（需 Redis + 模型网关 + AgentScope 运行期） | 见 TC-INT-*（手工/联调） |

**红线**：L3 用例全部依赖真实环境，本仓库仅交付「已接线且 L1/L2 编译通过」的代码，**不得据 L1 通过宣称生产可用**。

合计 **19** 个用例（12 个位于 `starter-agentscope`、7 个位于 `zhush-module-ai`），依赖 `zhush-spring-boot-starter-test`（JUnit5 + Mockito5 + AssertJ）。

### 1.2 设计说明（关键取舍）

- **不引入 reactor-test**：续跑通道用 Reactor 原生 `subscribe` + `CountDownLatch` 驱动，测试依赖最小化。
- **CAS 不测框架 SQL**：`casFinish` 由 MyBatis-Flex `UpdateChain` 构建异构链式（`where()` 返回 `QueryConditionBuilder`），对其 mock 脆弱且偏离被测目标；故将 `casFinish` 提升为**包级可见**，用 spy 打桩其布尔返回值，专注验证「分支选择 + 续跑触发/幂等跳过」这一自有逻辑。SQL 的 `resumed 0→1` 条件正确性由 L3 集成用例保证。
- **`runAfterCommit` 同步退化**：单测无活动事务同步，`TransactionSynchronizationManager.isSynchronizationActive()=false`，续跑回调同步执行，故可直接断言 `chatService.resumeNative(...)`。

## 2. 需真实环境的集成/手工验收用例（L3）

> 前置开关：`zhush.agentscope.native-state.enabled=true`、`zhush.agentscope.safety.native-confirm=true`，并具备 Redis（`RedissonClient`）与可用模型网关。相关接口：
> - 审批通过：`POST /admin/ai/agent/approval/approve`（权限 `agent:approval:approve`，body 含 `approvalId`、可含 `modifiedArgs`）
> - 审批驳回：`POST /admin/ai/agent/approval/reject`（权限 `agent:approval:reject`）
> - 对话流：`POST /admin/ai/agent/stream`（SSE）
> - **续跑流：`GET /admin/ai/agent/session/{sessionId}/resume-stream`（SSE）**

| 编号 | 场景 | 步骤 | 预期 |
| --- | --- | --- | --- |
| TC-INT-01 | 原生会话命中门禁 | 建原生会话（`native-state` 开）→ `stream` 触发敏感工具 | 收到 `REQUIRE_USER_CONFIRM`，`agent_approval` 落库且 `reply_id` 非空、`resumed=0`、`status=0` |
| TC-INT-02 | 审批通过后跨请求续跑 | 订阅 `resume-stream` → `approve` | 提交后 SSE 通道收到续跑事件流直至 FINISHED；`resumed` 变 1、`status=1`、`resume_time` 非空；会话状态置 2 |
| TC-INT-03 | 驳回续跑解释性收尾 | 订阅 `resume-stream` → `reject` | `confirmed=false` 喂回，`stopOnReject` 使框架产出终止/解释文本；`status=2` |
| TC-INT-04 | 改参续跑 | `approve` 携带 `modifiedArgs` | 以改后参数执行；`modified_args` 落库；续跑结果反映新参数 |
| TC-INT-05 | 重复审批幂等 | 对同一 `approvalId` 连续 `approve` 两次 | 第二次因 `status!=0` 或 CAS 未抢到而跳过，**仅续跑一次**，无重复事件/重复落库 |
| TC-INT-06 | 会话级灰度隔离 | 旧会话（建时 `native-state=false`）与新原生会话并存 | 旧会话仍走旧版 Redis 快路（`reply_id` 空），新会话走 CAS 续跑；两条 track 缓存键 `#legacy/#native` 互不污染 |
| TC-INT-07 | 状态单源不翻倍（负回归） | 原生会话多轮对话，观测 `agent_token_usage` 的 input token | 接 Redis 为**替换非叠加**：input token 不因本地 `JsonFileAgentStateStore` 与 Redis 双写而翻倍 |
| TC-INT-08 | 无 Redis 降级放行留痕 | 关 Redis 或令 `RedissonClient` 缺失、`fail-on-approval-store-unavailable=false` | 敏感工具按降级放行（不阻断对话），并输出 `log.warn` 降级留痕 |
| TC-INT-09 | 无 Redis 降级 fail-fast | 同上但 `fail-on-approval-store-unavailable=true` | 审批存储不可用时快速失败，绝不静默放行敏感操作 |
| TC-INT-10 | 门禁互斥 | `native-confirm=true` 且工具静态敏感 | 权限层 `ASK` 与工具层 `suspended` 不双触发（无死锁/双弹审批）；动态敏感词命中仍由工具层兜底 |
| TC-INT-11 | 续跑用户归属 | 提交人 A 触发挂起、审批人 B 通过 | 续跑以**首轮提交人 userId**（挂起态缓存）为 `state key`，而非审批人，保证 Redis 会话态命中一致 |

### L2 装配冒烟（可选，需 Spring 上下文、模型可 Mock）

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| TC-CTX-01 | `native-state.enabled=false` | `AgentStateStore` Bean 缺席（返回 null），`buildHarness` 走 `#legacy`，不接 Redis |

## 3. 配置开关矩阵

| 配置键 | 默认 | 作用 |
| --- | --- | --- |
| `zhush.agentscope.native-state.enabled` | `false` | 是否接入 Redis 原生状态存储（路线 B 总闸） |
| `zhush.agentscope.native-state.key-prefix` | `agentscope:state:` | `RedissonAgentStateStore` key 前缀 |
| `zhush.agentscope.safety.native-confirm` | `false` | 门禁是否迁移到权限层 `REQUIRE_USER_CONFIRM`（跨请求续跑） |
| `zhush.agentscope.safety.fail-on-approval-store-unavailable` | `false` | 无 Redis 时是否 fail-fast（否则降级放行并留痕） |

> relaxed binding；示例见各 `application-*.yaml`。灰度上线建议：**先**仅开 `native-state.enabled` 跑通 TC-INT-07（P4 负回归），**再**联调 `native-confirm` 的 TC-INT-01~06，全绿方上生产。
