# 通知公告模块实现方案

> 模块归属：`zhush-module-system`（管理端）
> 文档解析：复用已有 `POST /admin/system/file/parse-doc`
> 文档状态：**待确认**（确认后再进入功能编码）

## 一、需求概述

实现"通知公告"管理功能，包含以下功能点：

| 功能点 | 说明 |
|---|---|
| 新增 / 修改 | 维护公告：标题、类型、状态、内容（富文本） |
| 删除 | 逻辑删除公告 |
| 分页查询 | 按标题、类型、状态、时间等条件分页查询 |
| 富文本内容 | 内容使用富文本编辑器编辑 |
| 文档解析上传 | 支持 Word / PDF 上传，自动解析内容并回填富文本编辑器 |
| 公告查看记录 | 记录"谁看了公告"，支持按公告分页查看阅读记录 |

基础字段：**标题、类型、状态、内容**。

## 二、复用已有能力

本项目已具备以下基建，本模块**不重复造轮子**：

1. **文档解析能力**：`POST /admin/system/file/parse-doc`（`zhush-module-system` 的 `AdminFileController`）
   - 入参 `MultipartFile`（Word/PDF），出参 `DocParseResult { fileName, hasImage, text, html, images }`
   - `html` 字段：文本按段落包 `<p>` + 图片转 `<img src='文件外链'>`，可直接回填富文本编辑器
   - 权限 `system:file:create`，幂等 `@Idempotent(timeout=3)`
   - 前端直接调用即可，无需新增后端解析逻辑。
2. **后端 CRUD 规范**：参照 `AdminRole` 全链路（entity / mapper / query / param / vo / service / controller），统一使用：
   - `QueryWrapperX.create()` + `selectPageX` 分页
   - `converter.convert(param, Entity.class)` / `converter.convert(records, Vo.class)`
   - `@SaCheckPermission`（权限）、`@Idempotent`（幂等）、`@OperateLog`（操作日志）、`@Transactional`（事务）
   - `ServiceExceptionUtil.assertNotNull / assertTrue`（业务异常）
   - `PageResult<T>` / `Result<T>` 返回值
3. **雪花ID精度**：系统已全局将 `Long` 序列化为字符串，前端 `id` 一律按 `string` 处理（勿用 `Number()`）。
4. **菜单驱动**：前端页面路由与权限由 `sys_menu` 表 + `system:notice:*` 权限标识驱动。

## 三、数据库设计

新增 2 张表，均继承雪花ID主键 + 审计字段（`create_by` / `create_time` / `update_by` / `update_time` / `is_delete`）。

### 3.1 通知公告表 `sys_notice`

| 字段 | 类型 | 长度 | 空 | 说明 |
|---|---|---|---|---|
| id | BIGINT | - | 否 | 雪花ID主键 |
| title | VARCHAR | 200 | 否 | 公告标题 |
| type | TINYINT | - | 否 | 公告类型：1-通知 2-公告 3-警示 |
| status | TINYINT | - | 否 | 状态：0-草稿 1-已发布 2-已撤回 |
| content | LONGTEXT | - | 否 | 富文本 HTML 内容 |
| publish_time | DATETIME | - | 是 | 发布时间（status=1 时写入） |
| create_by | BIGINT | - | 是 | 创建人ID（插入时由 GlobalInsertListener 回填） |
| create_time | DATETIME | - | 是 | 创建时间 |
| update_by | BIGINT | - | 是 | 更新人ID（仅更新时回填，插入时为 NULL） |
| update_time | DATETIME | - | 是 | 更新时间 |
| is_delete | TINYINT | - | 否 | 逻辑删除：0-否 1-是 |

```sql
CREATE TABLE `sys_notice` (
  `id`            BIGINT       NOT NULL COMMENT '雪花ID主键',
  `title`         VARCHAR(200) NOT NULL COMMENT '公告标题',
  `type`          TINYINT      NOT NULL COMMENT '公告类型：1-通知 2-公告 3-警示',
  `status`        TINYINT      NOT NULL DEFAULT 0 COMMENT '状态：0-草稿 1-已发布 2-已撤回',
  `content`       LONGTEXT     NOT NULL COMMENT '富文本HTML内容',
  `publish_time`  DATETIME     NULL     COMMENT '发布时间',
  -- 审计列可空：insert 时 GlobalInsertListener 仅回填 create_by/create_time，update_by/update_time 为 NULL
  `create_by`     BIGINT       NULL     COMMENT '创建人ID',
  `create_time`   DATETIME     NULL     COMMENT '创建时间',
  `update_by`     BIGINT       NULL     COMMENT '更新人ID',
  `update_time`   DATETIME     NULL     COMMENT '更新时间',
  `is_delete`     TINYINT      NOT NULL DEFAULT 0 COMMENT '逻辑删除',
  PRIMARY KEY (`id`),
  KEY `idx_notice_title` (`title`),
  KEY `idx_notice_status` (`status`),
  KEY `idx_notice_type` (`type`),
  KEY `idx_notice_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='通知公告表';
```

### 3.2 公告查看记录表 `sys_notice_record`

| 字段 | 类型 | 长度 | 空 | 说明 |
|---|---|---|---|---|
| id | BIGINT | - | 否 | 雪花ID主键 |
| notice_id | BIGINT | - | 否 | 公告ID |
| user_id | BIGINT | - | 否 | 查看人ID |
| user_name | VARCHAR | 50 | 是 | 查看人姓名（冗余，便于列表展示） |
| view_time | DATETIME | - | 否 | 最近查看时间 |
| create_time | DATETIME | - | 否 | 首次查看时间 |

> 去重策略：**同一用户对同一公告仅保留一条记录**，重复查看时更新 `view_time`（`notice_id + user_id` 唯一索引）。

```sql
CREATE TABLE `sys_notice_record` (
  `id`          BIGINT      NOT NULL COMMENT '雪花ID主键',
  `notice_id`   BIGINT      NOT NULL COMMENT '公告ID',
  `user_id`     BIGINT      NOT NULL COMMENT '查看人ID',
  `user_name`   VARCHAR(50) NULL     COMMENT '查看人姓名',
  `view_time`   DATETIME    NOT NULL COMMENT '最近查看时间',
  `create_time` DATETIME    NOT NULL COMMENT '首次查看时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_notice_user` (`notice_id`, `user_id`),
  KEY `idx_record_notice` (`notice_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='公告查看记录表';
```

## 四、后端设计方案

### 4.1 模块与类清单（`com.zhush.system`）

| 分类 | 类名 | 说明 |
|---|---|---|
| entity | `SysNotice` | `@Table("sys_notice")` 继承 `BaseEntity` |
| entity | `SysNoticeRecord` | `@Table("sys_notice_record")` |
| mapper | `SysNoticeMapper` | `BaseMapper` + 自定义去重/分页查询 |
| mapper | `SysNoticeRecordMapper` | `BaseMapper` |
| query | `AdminNoticeQuery` | 继承 `BaseQuery`，字段：`title`、`type`、`status`、`createTimeBegin`、`createTimeEnd` |
| query | `NoticeRecordQuery` | 继承 `BaseQuery`，不额外字段（按公告维度分页） |
| param | `AdminNoticeParam` | 字段：`id`、`title`、`type`、`status`、`content`、`publishTime`（`@Valid` 校验） |
| vo | `AdminNoticeVO` | 继承 `BaseEntity` 审计字段，含 `title/type/status/content/publishTime` |
| vo | `NoticeRecordVO` | 含 `noticeId/userId/userName/viewTime` |
| service | `AdminNoticeService` | CRUD + 查看记录 + 记录查询 |
| controller | `AdminNoticeController` | 管理端接口，`@RequestMapping("/admin/system/notice")` |

### 4.2 接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/admin/system/notice` | `system:notice:create` | 新增公告 |
| PUT | `/admin/system/notice` | `system:notice:update` | 修改公告 |
| DELETE | `/admin/system/notice/{id}` | `system:notice:delete` | 删除公告（逻辑删除，级联清理查看记录） |
| GET | `/admin/system/notice/{id}` | `system:notice:query` | 公告详情 |
| GET | `/admin/system/notice/page` | `system:notice:query` | 公告分页 |
| POST | `/admin/system/notice/{id}/view` | 登录即可 | **记录当前用户查看公告**（Sa-Token 取当前登录人，去重 upsert） |
| GET | `/admin/system/notice/{id}/record` | `system:notice:query` | 分页查询该公告的查看记录 |

### 4.3 核心逻辑说明

1. **新增公告**：`@Transactional`，`converter.convert(param, SysNotice.class)`，`status=1` 时写入 `publish_time`，`insert` 后返回 `id`。
2. **修改公告**：`selectOneById` 校验存在（`assertNotNull`），若 `status` 变为 `1` 且原状态非 `1`，刷新 `publish_time`；`update`。
3. **删除公告**：`deleteById`（逻辑删除），并删除该公告全部查看记录（`noticeRecordMapper.deleteByNoticeId(id)`）。
4. **查看公告记录**：`POST /{id}/view`
   - 当前登录人：`StpUtil.getLoginId()`（Long，雪花）；姓名：查询用户表取 `nickname`/`username`。
   - 去重 upsert：先按 `(notice_id, user_id)` 查记录，存在则更新 `view_time`；不存在则插入（用唯一索引兜底 + `insert` 时捕获重复）。
   - 记录时校验 `SysNotice` 存在且 `status=1`（已发布才可被查看）。
5. **查询公告分页**：`QueryWrapperX.create()`
   - `.like(SysNotice::getTitle, query.getTitle())`
   - `.eq(SysNotice::getType, query.getType())`
   - `.eq(SysNotice::getStatus, query.getStatus())`
   - `.ge(SysNotice::getCreateTime, query.getCreateTimeBegin())` / `.le(...End)`
   - `.orderBy("create_time", false)`（最新在前）
   - `selectPageX(query, queryWrapper)` + `converter.convert` + `PageResult.of(...)`
6. **查询查看记录**：`QueryWrapperX.create().eq(SysNoticeRecord::getNoticeId, noticeId)` + `orderBy("view_time", false)` + 分页。

### 4.4 权限与审计

- 所有写操作加 `@Idempotent`，`@OperateLog(module="通知公告", type=... )`，权限标识 `system:notice:*`。
- 查看记录接口 `POST /{id}/view` 不强制 `system:notice:*`，登录即可（为后续普通用户端阅读复用）；管理端分页查询记录需 `system:notice:query`。

## 五、前端设计方案

### 5.1 页面与组件（`src/views/system/notice`）

| 文件 | 说明 |
|---|---|
| `index.vue` | 列表页：`usePageQuery` 分页 + `useVbenForm` 查询区 + 工具栏（密度/列设置/序号列，参照 `role/index.vue`） |

| `modules/record.vue` | 查看记录弹窗：表格展示 `userName` / `viewTime`，分页 |

### 5.2 富文本编辑器选型

项目 Vue3 + antdv-next，**未内置富文本编辑器**，需新增依赖。建议：

| 方案 | 依赖 | 优点 | 备注 |
|---|---|---|---|
| **wangEditor（推荐）** | `@wangeditor/editor` + `@wangeditor/editor-for-vue@next` | 轻量、中文友好、内置图片/菜单定制，Vue3 原生支持 | 采用，风险低 |
| TinyMCE | `@tinymce/tinymce-vue` | 功能强 | License/GPL + 体积大，需谨慎 |
| Quill | `@vueup/vue-quill` | 简单 | 中文与图片处理弱 |

> 选型为建议值，**待你确认后再引入**；如已有偏好可替换。

### 5.3 文档上传解析 → 回填富文本

1. 表单内放置"上传 Word/PDF 解析"按钮（或上传框），选择 `.doc/.docx/.pdf` 文件。
2. 前端组装 `FormData`，调用 `POST /admin/system/file/parse-doc`。
3. 取响应 `data.html`，通过编辑器 API `editor.setHtml(html)` 回填（wangEditor）或 `editor.setContent(html)`（TinyMCE）。
4. 解析结果中的图片已是文件服务外链，直接可用。
5. 解析成功提示"解析成功，内容已回填"。

## 七、实施步骤与验收

### 7.1 实施步骤

1. **SQL**：新增 `sql/14_notice.sql`（建表 + 菜单权限，菜单 id：106 通知公告 / 160-163 按钮权限）。
2. **后端**：编码 entity / mapper / query / param / vo / service / controller，遵循现有 `AdminRole` 规范。
3. **前端**：
   - 引入富文本编辑器依赖（wangEditor）。
   - 编码 `api/system/notice.ts`、`views/system/notice/*`。
   - 菜单在 `sys_menu` 注册后自动出现在路由。
4. **联调**：文档上传解析 → 富文本回填全链路验证。

### 7.2 验收标准

- 管理端可对公告做增删改查、条件分页。
- 内容可富文本编辑；上传 `.doc/.docx/.pdf` 后内容被解析并回填编辑器。
- 阅读某公告后，管理端"查看记录"能看到"谁看了、何时看"。
- 同一用户重复查看同一公告不产生重复记录（view_time 刷新）。
- 删除公告后其查看记录一并清理。
- 雪花ID在前端以 `string` 传输，无损。

## 八、风险与边界

| 项 | 说明 |
|---|---|
| 富文本编辑器依赖 | 需新增 npm 依赖并保证与 Vue3/antdv-next 兼容；建议锁定版本 |
| 文档解析体积 | 大文档解析耗时，`parse-doc` 已带 3s 幂等；前端可加"解析中"loading |
| 扫描版PDF | 未集成 OCR，仅能提取图片、无文本（复用现有 `parse-doc` 限制） |
| XSS 安全 | 富文本 `content` 需后端/前端做 XSS 过滤（sanitize），入库前清洗 |
| 查看记录口径 | 采用"每用户每公告一条（upsert）"，杜绝记录膨胀；若需完整审计流水，可改为每次查看一条 |
