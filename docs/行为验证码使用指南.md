# 行为验证码使用指南

> 模块：`zhush-spring-boot-starter-captcha`（框架层，基于 [tianai-captcha](https://gitee.com/anji-plus/captcha) 1.5.5 核心库）
>
> 能力：**行为验证码**（滑块 / 旋转 / 拼图），管理端与会员端登录共用，答案存 Redis 支持多实例部署。

---

## 一、功能总览

| 能力 | 实现方式 | 说明 |
| --- | --- | --- |
| 验证码生成 | `CaptchaService.generate()` | 返回背景图 + 模板图（Base64），前端渲染交互组件 |
| 验证码校验 | `CaptchaService.validate(id, data)` | 一次性使用，校验后（无论成败）立即失效 |
| 登录前置校验 | `AdminAuthService` / `MemberAuthService` | 登录链路第一步校验，失败不触碰数据库 |
| 答案存储 | `RedisCacheStore` | 实现 tianai `CacheStore` 接口，key 前缀 `zhush:captcha:` |
| 自由启停 | `zhush.captcha.enabled` | `false` 时不装配任何 Bean，业务侧自动跳过（零侵入） |

**技术选型说明**：仅引入 tianai-captcha **核心库**（纯 Java、只依赖 slf4j），未使用官方 `tianai-captcha-springboot-starter`，规避其与 Spring Boot 4 的自动装配兼容风险；装配序列对齐官方 starter 反编译结果。

---

## 二、启用与配置（两级启停）

### 1. 配置开关（application-dev.yaml）

```yaml
zhush:
  captcha:
    enabled: true          # 总开关：false 不装配任何验证码 Bean，登录自动跳过校验
    login-required: true   # 登录是否强制校验验证码（false 时验证码接口仍可用，仅登录不校验）
    type: SLIDER           # 玩法：SLIDER-滑块拼图 ROTATE-旋转 CONCAT-组合拼图
    image-format: WEBP     # 图片输出格式：WEBP / JPEG_PNG
    expire-seconds: 120    # 验证码有效期（秒），超时校验失败
```

### 2. 启停语义

| 级别 | 配置 | 效果 |
| --- | --- | --- |
| 1 总开关 | `zhush.captcha.enabled: false` | 不注册任何 Bean；`/captcha` 端点返回 `null`，登录跳过校验 |
| 2 登录开关 | `zhush.captcha.login-required: false` | 验证码接口可用，但登录不强制校验（联调 / 内部环境常用） |

业务侧通过 `ObjectProvider<CaptchaService>` 可选注入，Bean 不存在时自动降级，**无需改业务代码即可关闭功能**。

### 3. 模块接入（pom）

```xml
<dependency>
    <groupId>com.zhush</groupId>
    <artifactId>zhush-spring-boot-starter-captcha</artifactId>
</dependency>
```

`zhush-module-system`（管理端）与 `zhush-module-member`（会员端）已接入。依赖 `zhush-spring-boot-starter-redis`（答案存储），版本由 `zhush-dependencies` BOM 统一管理。

## 三、已接入接口

### 1. 获取验证码

| 端 | 接口 | 鉴权 |
| --- | --- | --- |
| 管理端 | `GET /admin/auth/captcha` | 免登录（`@IgnoreAuth`） |
| 会员端 | `GET /member/auth/captcha` | 免登录（`@IgnoreAuth`） |

响应（验证码关闭时 `data` 为 `null`，前端据此跳过验证码流程）：

```json
{
  "code": 0,
  "data": {
    "id": "c-xxxx",
    "type": "SLIDER",
    "backgroundImage": "data:image/webp;base64,...",
    "templateImage": "data:image/webp;base64,...",
    "backgroundImageWidth": 288,
    "backgroundImageHeight": 155,
    "templateImageWidth": 47,
    "templateImageHeight": 47,
    "data": null
  }
}
```

### 2. 登录接口携带验证码

`POST /admin/auth/login`（管理端）与会员端账号登录接口请求体新增两个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `captchaId` | String | 获取验证码接口返回的 `id`（开启验证码时必传） |
| `captchaData` | String | 用户行为数据，如滑块位移量（开启验证码时必传） |

校验失败错误码：

| 端 | 错误码 | 常量 |
| --- | --- | --- |
| 管理端 | `1001005` | `SystemErrorCode.CAPTCHA_INVALID` |
| 会员端 | `1002006` | `MemberErrorCode.CAPTCHA_INVALID` |

### 3. 前端对接流程

```
1. GET  /xxx/auth/captcha            → 渲染背景图 + 模板图（Base64 直接用于 <img src>）
2. 用户拖动滑块 / 旋转图片            → 记录行为数据（如位移量 px）
3. POST /xxx/auth/login              → body 携带 captchaId + captchaData（位移量转字符串）
4. 校验失败（1001005 / 1002006）      → 重新获取验证码重试（验证码一次性，不可复用）
```

## 四、编程式使用（扩展到新场景）

注入 `CaptchaService`（推荐用 `ObjectProvider` 以兼容开关关闭场景）：

```java
public class XxxService {

    private final CaptchaService captchaService;

    public XxxService(ObjectProvider<CaptchaService> captchaServiceProvider) {
        this.captchaService = captchaServiceProvider.getIfAvailable();
    }

    public void bizWithCaptcha(String captchaId, String captchaData) {
        // 开关关闭时 captchaService == null，直接跳过
        if (captchaService != null) {
            assertTrue(captchaService.validate(captchaId, captchaData), ErrorCode.CAPTCHA_INVALID);
        }
        // ... 业务逻辑
    }
}
```

## 五、自定义与扩展

所有核心 Bean 均标注 `@ConditionalOnMissingBean`，可按需覆盖：

| Bean | 默认实现 | 覆盖场景 |
| --- | --- | --- |
| `CacheStore` | `RedisCacheStore`（Redis 存储） | 换用本地缓存 / 自定义序列化 |
| `ImageCaptchaApplication` | TACBuilder 默认装配（SLIDER + SimpleImageCaptchaValidator） | 更换玩法模板 / 校验容差 / 干扰策略 |
| `CaptchaService` | 统一门面 | 增加审计日志 / 频控 |

示例——自定义校验器（放宽 / 收紧轨迹容差）：

```java
@Bean
public ImageCaptchaApplication imageCaptchaApplication(CacheStore captchaCacheStore, CaptchaProperties properties) {
    // 自行组装 TACBuilder，替换 validator / generator / 模板资源
}
```

Redis key 约定：`zhush:captcha:{验证码ID}`，值含答案坐标，TTL 与 `expire-seconds` 一致，校验后即删除。

## 六、注意事项

1. **一次性**：验证码校验后立即失效（含失败），前端失败后必须重新获取。
2. **有效期**：默认 120 秒，超时校验返回失败；`expire-seconds` 可调。
3. **图片格式**：`WEBP` 体积小但需确认前端渲染环境支持；不支持时可切 `JPEG_PNG`。
4. **多实例**：答案存 Redis，任一节点生成、任一节点校验均可。
5. **关闭语义**：`enabled: false` 后 `/captcha` 返回 `data: null`，登录不校验——生产环境不建议关闭。
6. **测试**：单测中 mock `ObjectProvider<CaptchaService>` 且 `getIfAvailable()` 默认返回 `null`，不影响存量登录用例；验证码专项用例见 `AdminAuthServiceTest`。
