## 一、交付范围与结论

本次严格遵循方案的四大核心能力全部落地并通过验证：

| 能力 | 状态 | 关键载体 |
| --- | --- | --- |
| ① 资源登记 | ✅ | `sys_data_resource` + `DataResourceMetadataSyncer`（注解反射扫描，幂等登记/刷新） |
| ② 行级规则细化（按业务对象覆盖） | ✅ | `sys_role_data_resource`（scope 1-6）+ `AdminDataScopeProvider` 资源级解析 + `DataPermissionDialect` 资源编码传递 |
| ③ 列级字段授权 | ✅ | `sys_data_field`（元数据）+ 复用 `sys_menu` type=3 权限点 + `FieldPermissionResolver` |
| ④ 自定义条件（白名单 JSON，不做 SpEL） | ✅ | `RowConditionCompiler`（字段/操作符双白名单 + 参数化 + `$self` 后端注入） |

验证结果（Maven 离线 + vue-tsc）：

- `zhush-spring-boot-starter-biz-data-permission`：**24 项单测全绿**（含新增方言 `DataPermissionDialectTest` 7 项）。
- `zhush-module-system`：**93 项单测全绿**（含新增 `RowConditionCompilerTest` 11、`AdminDataScopeGuardTest` 7、`FieldPermissionResolverTest` 5）。
- 前端 `@vben/web-antdv-next`：`vue-tsc --noEmit` **零错误**。

## 二、文件清单（按层）

### 2.1 框架层（正向取证 + 增量改造，向后兼容）
- `annotation/DataPermission.java`：新增 `String resource() default ""`。
- `core/DataScope.java`：新增 `extraConditions` + `addExtraCondition` + `hasExtraConditions`。
- `core/DataScopeProvider.java`：新增默认方法 `getDataScope(String resourceCode)`（默认委派无参版）。
- `core/dialect/DataPermissionDialect.java`：按 `annotation.resource()` 路由资源/全局解析；`extraConditions` 与基础条件 AND 合并；去掉 ALL 早返回，改为 `buildCondition` 对 ALL 返回 null；注入条件统一 `queryWrapper.and(QueryMethods.bracket(condition))`（OR 红线）。

### 2.2 业务模块层（`zhush-module-system`）
- 实体：`SysDataResource` / `SysDataField` / `SysRoleDataResource`（`SCOPE_*` 常量 1-6）。
- Mapper：三表 Mapper + `SysMenuMapper.selectByPermission`。
- 安全组件：`RowConditionCompiler`（白名单编译/校验）、`AdminDataScopeGuard`（byId 越权护栏）、`FieldPermissionResolver`（DB 读取角色字段权限点）。
- `AdminDataScopeProvider`：改为 5 参构造 + 快照缓存（默认范围 + 按资源覆盖 map，含 scope=6 编译）；60s TTL + `invalidateAll/invalidate`。
- `AdminPermissionChecker`：委托 `FieldPermissionResolver`。
- `AdminUserService`：`getUserPage` 补 `resource="system:user"`；update/delete/get/assignRoles/resetPassword 共 5 处 byId 落护栏。
- `AdminRoleService`：删除角色级联清理 `sys_role_data_resource`。
- 服务：`DataResourceMetadataSyncer`、`DataResourceService`、`RoleDataPermissionService`。
- 控制器：`AdminDataResourceController`、`AdminRoleController` 新增 4 个行/列接口。
- VO/param/query 共 10 个；`SystemErrorCode` 增 3 码（含 `ROLE_DATA_CONDITION_INVALID`）。

### 2.3 数据库层
- `sql/32_data_permission_config.sql`：三表幂等建表（`DROP IF EXISTS + CREATE`）+ 数据资源管理菜单/按钮种子（106 / 160-162）+ 内置 `system:user` 资源与 3 字段种子（复用 31 号脚本的 116-118 权限点）+ 文件末尾回滚段。

### 2.4 前端层（`apps/web-antdv-next`）
- `api/system/data-permission.ts`（新增，并在 `api/system/index.ts` 导出）。
- `views/system/data-resource/{index.vue, data.ts, modules/form.vue, modules/fields.vue}`（数据资源管理页）。
- `views/system/role/modules/data-permission.vue`（角色数据权限两 Tab 弹窗）。
- `views/system/role/index.vue`：新增"数据权限配置"按钮 + 弹窗接入。

## 三、原型/方案 vs 实际实现 差异对照

| 编号 | 方案/原型设计 | 实际实现 | 原因 |
| --- | --- | --- | --- |
| D-1 | `condition_json`：`{"match":"AND","rules":[{"op":"ge"},{"op":"eq_param","value":"SELF"}]}` | `{"logic":"AND","conditions":[{"field","op":">="},{"value":"$self"}]}` | 采用符号操作符 + `$self` 令牌，语义更直观；方案 §3.4 为示意结构 |
| D-2 | `sys_role_data_resource.resource_id`（FK） | `resource_code`（varchar） | 资源 code 全局唯一，按 code 查询/覆盖更直接，省去 join |
| D-3 | 可过滤列白名单建议独立表 `sys_data_resource_field` | 折叠为 `sys_data_resource.filter_columns`（逗号串） | 降低表数量与同步复杂度，够用 |
| D-4 | `sys_data_field.default_strategy` tinyint(1/2) | varchar('CLEAR'/'MASK') | 直接镜像 `@FieldPermission.strategy().name()`，避免枚举映射漂移 |
| D-5 | 数据资源页用 VxeGrid + 展开行显示字段 | antdv `Table` + "受控字段"弹窗（内含只读详情 + 字段启停） | 对齐仓库既有页面技术栈（role/user 均用 antdv Table）；`expandedRowRender` 在本仓无先例，改弹窗更稳 |
| D-6 | 行级自定义条件用"条件构造器"（字段/操作符/值下拉） | 白名单 JSON **文本编辑器** + 保存侧后端校验 | 一次性交付取舍；构造器列为遗留增强（见 R-2） |
| D-7 | 列级"零改造" | 新增 `FieldPermissionResolver` 并被 `AdminPermissionChecker` 委托 | 用户显式要求"新增 FieldPermissionResolver 从 DB 读取字段权限点"；判定口径仍是 `sys_menu`，行为等价、单一事实来源不变 |
| D-8 | R-2 byId 越权"另行排期，非本方案范围" | 已在 Service 层强制落地（`AdminDataScopeGuard` + 5 处） | 用户交付要求"byId 越权护栏必须在 Service 层强制落地" |
| D-9 | `GET /role/{id}/data-permission` 权限 `assign-data-scope` | GET 用 `system:role:query`；PUT 行用 `assign-data-scope`、PUT 列用 `assign-menu` | 读用查询权限更符合最小授权；写沿用既有权限点不新增 |
| D-10 | 唯一键 `uk_code(code,is_delete)` | `uk_code(code)` | 逻辑删除下 code 复用概率极低，简化唯一约束（如需可加 is_delete） |

## 四、红线与约定落地核对

- **OR 短路红线（R-1）**：方言注入统一 `and(QueryMethods.bracket(condition))`；`RowConditionCompiler` 编译产物不接受业务裸 OR，多条件由 `logic` 字段控制并以括号并入。单测 `injectedConditionIsBracketedAgainstExistingOr` 断言 `... AND (dept_id IN (...))` 括号形态。
- **byId 越权护栏（R-2）**：`selectOneById` 不经方言，`AdminDataScopeGuard.assertVisible(deptId, ownerId, denyCode, args)` 在 5 个按主键入口显式校验，越权统一按"资源不存在"抛出，避免存在性泄露。
- **自定义条件注入（F-2）**：字段白名单（命中不了整条丢弃、读取侧 fail-closed）+ 操作符白名单（9 种）+ 一律经 `QueryColumn` 绑定参数 + `$self` 由后端注入当前用户ID（前端不得传真实ID）。
- **列级单一口径（F-4）**：列级授权仍复用 `sys_menu`/`sys_role_menu`，同步器幂等登记字段按钮（type=3）挂"字段权限"目录，不建第二套授权存储；`FieldPermissionResponseAdvice` 未改动。
- **序列化约定（用户强调）**：部门ID 前端传数组（`string[]`）、后端 `RoleDataPermissionService` 转逗号串落库 / 读取还原数组；主键雪花 Long 由全局 Jackson 序列化为字符串，前端按 `string` 处理。
- **缓存 TTL（用户强调）**：`AdminDataScopeProvider` 快照 60s（`CACHE_TTL_MILLIS=60_000L`）；资源/字段/角色规则写操作后 `invalidateAll()`；角色删除级联清理规则。

## 五、遗留风险与后续建议

| 编号 | 风险/缺口 | 影响 | 建议 |
| --- | --- | --- | --- |
| R-1 | 元数据同步器**只登记不清理**：代码中移除 `@DataPermission`/`@FieldPermission` 后，DB 资源/字段行不会自动删除 | 可能残留陈旧资源（可用 status 停用缓解） | 增加"孤儿资源识别 + 软停用"或同步 diff 报告 |
| R-2 | 自定义条件为**自由文本 JSON**，非下拉构造器（D-6） | 运维易写错（后端已拦截非法项，但体验差） | 阶段三补条件构造器（字段/操作符/值，字段取自资源白名单） |
| R-3 | 行级资源覆盖仅对**接入 `@DataPermission` 且有 QueryWrapper 的语句**生效；Mapper XML 原生 SQL / byId 不经方言 | 与既有框架边界一致 | 各业务表接入按 checklist 显式护栏；补集成测试 |
| R-4 | byId 护栏当前仅落地 `AdminUserService`（system:user 资源）；其他资源未接入 | 其他对象详情/写操作仍可能越权 | 按各自 checklist 逐步接入 `AdminDataScopeGuard` |
| R-5 | 导出链路列级盲区（F-3）未处理：导出不经 `ResponseBodyAdvice` | 敏感列仍可能从导出泄露 | `sys_data_field` 增 `has_export` 标记并在导出手工过滤（单独排期） |
| R-6 | 多实例缓存最迟 60s 收敛（文档口径） | 跨节点短时不一致 | 如需即时可引入 Redis 广播失效 |
| R-7 | 角色"数据权限配置"弹窗行级 Tab 的确认会同时提交默认范围（`assignRoleDataScope`）与行级覆盖；默认范围=5 且未选部门时未做前端拦截 | 潜在空自定义部门保存 | 前端补默认部门校验（与旧 `data-scope.vue` 一致） |
| R-8 | `FieldPermissionResolver.hasPermission` 每次调用读取 `getPermissionList`（未做请求级缓存） | 单响应内多受控字段可能多次 DB 解析（Sa-Token token-session 已缓存，影响有限） | 后续可请求级 memo 化 |
| R-9 | 仅单元/编译级验证，**无 DB 集成/E2E** | 方言实际拼 SQL、同步器真实反射未跑通 | 接入集成测试环境后补跑；灰度前手工点验同步 + 两类页面 |
| R-10 | 菜单种子固定 id（106/160-162、3001、3101-3103）为演示分配 | 若现网已占用需调整 | 上线前核对现网 `sys_menu`/新表 id 区间，必要时改脚本 |

## 六、上线操作提示

1. 先执行 `sql/32_data_permission_config.sql`（幂等，可重复执行；含回滚段说明）。
2. 开启总开关 `zhush.data-permission.enabled=true`（行/列分别有 `row-enabled`/`field-enabled` 子开关）。
3. 进入「系统管理 → 数据资源管理」点击**元数据同步**，登记各业务对象与受控字段。
4. 在「角色管理 → 数据权限配置」按需设置行级覆盖与列级授权；未覆盖资源回落 `sys_role.data_scope` 默认。
5. 回滚见脚本末尾"回滚段"，仅移除页面化能力，不影响 31 号脚本权限点与 `data_scope` 既有语义。
