## 三、现存问题清单

### 🔴 P0（必须修复）— 无

此前两项 P0（union 权限裸奔、union 未接入 server）均已闭环。

### 🟡 P1（重要）

#### 1. 资金链路测试覆盖（已闭环）
- **现状**：已新建 `zhush-spring-boot-starter-test` 测试 starter（JUnit5 + Mockito + AssertJ + StarterTestSupport 冒烟基类），父 pom 统一 surefire 3.2.5。第一批 56 个测试全绿（starter 装配冒烟 + JobUtils/RocketMQUtils/WebSocket 核心封装 + JacksonUtils）。
- **第二批（2026-08-18 闭环）**：system 权限链路 38 个单测（AdminAuthService 登录/BCrypt/同端互踢/禁用拦截/getUserInfo，AdminPermissionService RBAC 解析，AdminUserService/AdminRoleService CRUD 与数据范围）+ union 资金链路 24 个契约单测（佣金记录/提现申请/推广者账户的防呆校验 1003301/1003501/1003701、转换、分页）。全模块 118 个测试全绿。
- **剩余**：无。union 现有 service 均为 CRUD 模板（无独立佣金计算/提现状态机逻辑），契约测试已覆盖全部防呆分支；后续若新增资金计算/状态机逻辑，需同步补单测（核心链路行覆盖率 ≥ 60%）。

#### 2. 多环境配置滞后（prod/test/docker/my）
- **现状**：仅 dev 与最新 starter 体系对齐；`application-prod.yaml` 缺 `spring.data.redis`、file、idempotent、cors、job/mq/websocket 配置块，且含占位密码（`your_password`、`your-16-char-key`）、保留 dev 已删除的 slave 数据源。
- **方案**：以 dev 为基准对齐 4 套 profile；敏感值改环境变量注入（`${DB_PASSWORD}`）；生产关闭 knife4j/springdoc/Druid 控制台。

#### 3. MQ/WebSocket 运行时未联调
- **现状**：仅编译验证；RocketMQ 未连真实 Broker，`zhush.websocket.heartbeat-interval` 属性已定义但未接入心跳 Ping，会话注册表为单机内存。
- **方案**：本地起 RocketMQ 做一次收发联调；WebSocket 补心跳定时任务（清理失效会话）；多实例部署前评估 Redis Pub/Sub 跨节点推送。

### 🟢 P2（优化）

#### 4. SQL 资产重复 ✅ 已整改（2026-08-17）
- diff 结论：`zhush_union.sql`（Navicat 导出，56 表）是 `union.sql`（手工精简，46 表）的**严格超集**——覆盖全部 46 表且无字段缺失，另多 10 张 sys_* 表与 4 条超管种子数据（admin/角色/部门）；`union.sql` 自身还有重复建表缺陷（`union_member_account`、`union_account_transaction` 各建两次）。
- **结果**：`git mv zhush_union.sql → 09_union.sql`（保留 git 历史），删除 `union.sql`；sql/ 目录现有 9 份编号脚本，无重复资产。

#### 5. 空壳模块占用构建链
- `zhush-module-pay`（0 文件）、`zhush-module-ai`（1 文件）挂在 parent modules 但未接入 server。
- **方案**：近期排期实现则保留；否则暂从 parent `<modules>` 移除。

#### 6. 安全收敛
- dev CORS `allowed-origin-patterns: "*"`；Redis 密码 `123456`；Druid 控制台弱口令；SM4 key 占位符。
- **方案**：生产 profile 逐项收敛（与 P1-2 一并处理）。
