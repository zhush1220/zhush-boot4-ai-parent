## 一、模块定位与总览

### 1.1 业务闭环

电商联盟（CPS 推广返佣）已打通的完整链路：

```text
选品 → 同步 → 转链 → 短链 → 点击
      → 下单 → 归因 → 计佣 → 分配 → 结算入账
      → 账户资金 → 提现申请 → 风控 → 审核 → 打款（微信/银行卡）→ 到账
      → 通知 → 团队快照 → 会员端聚合
```

- **一期**：选品 → 同步 → 转链 → 短链 → 点击（真实平台以 Mock 兜底）。
- **二期**：下单 → 归因 → 佣金规则 → 计佣 → 分配 → 退款冲正。
- **三期**：账户资金 → 结算入账 → 提现（申请/风控/审核/打款）→ 外部推广者双轨。
- **四期**：消息通知（仅入库）→ 会员端接口 → 团队快照。
- **支付专项**：微信商家转账（v3）与银行卡出账（v2）渠道 + 回调/查单/撤销/对账落库。

## 二、菜单、权限与路由

### 2.1 菜单 ID 规划

| 段 | 用途 |
| --- | --- |
| `2200` | 联盟推广一级目录（根） |
| `2201~2208` | 8 个二级业务目录 |
| `2100~2143` | 44 个页面菜单（type=2） |
| `21001~21499` | 按钮权限点（type=3，按钮 ID = 菜单 ID×10 + 序号） |
| `21285 / 21395 / 21396` | 特殊按钮：商品同步 / 提现审核 / 提现打款 |

### 2.2 路由约定（**相对段**，重要）

- 后端 `AdminMenuService.resolveFullPath` 会**逐级拼接祖先 `path`**（先去掉前缀 `/` 再 join），
  因此 `sys_menu.path` 必须写**相对段**，否则 URL 会出现重复段（如 `/union/union/promotion/union/xxx`）。
- 本模块约定：一级 `union`、二级业务组段（`promotion`/`goods`/…）、叶子资源段（`product`/`order`/…）。
- 最终 URL 形如 `/union/{组段}/{资源段}`，例如推广链接为 `/union/promotion/promotion-link`。
- `component` 仍写绝对路径 `/union/{key}/index`，对应前端 `views/union/{key}/index.vue`，**不受相对段影响**。

### 2.3 权限点

- 标准资源：`union:{key}:{query|create|update|delete}`，例如 `union:category:query`、`union:product:sync`。
- 特殊权限：`union:product:sync`（商品同步）、`union:withdraw-apply:audit`（提现审核）、`union:withdraw-apply:pay`（提现打款/撤销/查单）。
- 前端按钮用 `v-access:code` 控制显隐；后端用 `@SaCheckPermission(type=CommonConstant.TYPE, value="...")` 强校验。

### 2.4 角色授权

`08_union_menu.sql` 末尾以 `INSERT ... SELECT id, 1, id FROM sys_menu WHERE id BETWEEN 2100 AND 2208 OR id BETWEEN 21000 AND 21499`
为超级管理员（role_id=1）授予全部联盟菜单与按钮。**`sys_role_menu.id` 直接取 `menu_id`**，规避与其他脚本授权行主键冲突。

> ⚠️ 该脚本是幂等的：先 `DELETE` 2100~2208 与 21000~21499 再重建。**调整菜单后直接重跑脚本即可**刷新数据库，无需手动清表。

## 三、运行前置与配置

### 3.1 建表

执行 union 相关建表脚本（约 44 张 `union_*` 表），确认业务库可连接。Quartz 任务需 `sql/07_quartz.sql`（JDBC 持久化）。

### 3.2 关键配置项（`application-dev.yaml`）

```yaml
zhush:
  union:
    platform:                        # 平台接入（各平台 enabled=false → Mock）
      enabled: true
      default-strategy: official     # official / aggregate(大淘客备降)
      taobao: { enabled: false, app-key: "", app-secret: "", pid: "", adzone-id: "", site-id: "" }
      jd:     { enabled: false, app-key: "", app-secret: "", position-id: "" }
      pdd:    { enabled: false, client-id: "", client-secret: "", pid: "" }
      datoke: { enabled: false, api-key: "", base-url: https://openapi.dataoke.com }
    link:
      short-url-domain: http://localhost:9166/api/s   # 短链前缀（含 context-path）
      default-expire-days: 30
      invalid-url: http://localhost:5999/union/link-invalid
    job:
      product-sync-cron: 0 0/30 * * * ?
  pay:
    wx:
      enabled: false                 # true 时注册微信渠道；凭证缺失会启动失败（fail-fast）
      app-id: ${WX_PAY_APPID:}
      mch-id: ${WX_PAY_MCHID:}
      mch-serial-no: ${WX_PAY_MCH_SERIAL:}
      api-v3-key: ${WX_PAY_APIV3KEY:}
      private-key-path: classpath:cert/apiclient_key.pem
      notify-url: ${WX_PAY_NOTIFY_URL:}
      transfer-scene-id: "1005"
      min-amount: "0.01"
      max-amount: "2000.00"
      bank:                          # 企业付款到银行卡（v2），独立开关与凭证
        enabled: false
        mch-key: ${WX_PAY_V2_KEY:}
        cert-path: classpath:cert/apiclient_cert.p12
        min-amount: "0.01"
        max-amount: "20000.00"
```

### 3.3 依赖开关

| 开关 | 作用 |
| --- | --- |
| `zhush.job.enabled=true` | 定时任务注册总开关（否则不注册，仍可手动触发同步） |
| `zhush.union.platform.enabled=true` | 适配层总开关（当前不影响 Mock 装配，见 §5.1） |
| `zhush.pay.wx.enabled=true` | 注册微信渠道与微信回调端点 |
| `zhush.mq.enabled=false` | MQ 未启用（订单走推送+轮询） |
| `zhush.websocket.enabled=false` | 通知仅入库 |

### 3.4 ⚠️ 生产配置缺失（重要）

**`application-prod.yaml` / `application-test.yaml` / `application-docker.yaml` 均未配置 `zhush.union.*` 段**（仅 `application-dev.yaml` 有）。
因此非 dev 环境会回退**代码默认值**：

- 短链域名默认 `http://localhost:9166/api/s`（`UnionLinkProperties.shortUrlDomain`）→ **生产短链会指向 localhost，不可用**；
- 失效兜底页默认 `http://localhost:5999/union/link-invalid`。

> **上线前必须在对应环境补齐 `zhush.union.link.short-url-domain` 等配置**（公网可达域名，含 context-path）。
> 同理，确需真实平台/微信打款时，需在各环境补齐 `zhush.union.platform.*` 与 `zhush.pay.wx.*` 凭证。

| `unionSettleJob` | union | `0 0/10 * * * ?` | `zhush.union.job.settle-cron` | 会员逐单结算 + 外部自动轨 |

## 五、横切能力

### 5.1 平台适配层（`adapter`）

- **SPI**：`UnionPlatformClient` 定义 `queryProducts / queryProductDetail / generateLink / pullOrders`。
- **路由**：`PlatformClientFactory` 按平台枚举路由；未注册平台抛 `PLATFORM_CLIENT_UNAVAILABLE`。
- **⚠️ 当前恒为 Mock**：`UnionAdapterConfig` **无条件**为淘宝/京东/拼多多/抖音各注册一个 `MockPlatformClient`；
  `zhush.union.platform.*.enabled` 与 `default-strategy` **目前未参与条件装配**。即：真实凭证到位前，
  选品/转链/拉单全部返回确定性 Mock 数据（同一查询可复现）。
- **接入真实平台时**：需在 `UnionAdapterConfig` 按 `enabled` 条件装配真实 Bean 并替换 Mock（`@Primary`/条件装配），core 与前端零改动。

### 5.2 平台 API 调用日志

- `@PlatformApiLog("xxx")` 标注平台实现方法，`PlatformApiLogAspect` 统一记录 apiName/入参（截断 2000）/响应码/耗时/成功标志到 `union_api_call_log`。
- **落库失败只告警，绝不阻断主流程**。

### 5.3 商品三级缓存（`ProductQueryService`）

- 层级：本地 `ConcurrentHashMap`（TTL 30s，容量 1000 超限整体清空）→ Redis（TTL 5min）→ DB。
- **仅商品详情走三级缓存，列表/推荐不缓存**（避免查询组合膨胀）。
- 商品新增/更新/状态变更时 `evict(id)` 精准失效本地 + Redis。

### 5.4 业务 AI 智能体（`ai`）

`UnionAgentDefinitionProvider` 注册 5 个智能体（分组 `biz`，默认模型 `qwen-max`，`streaming=true`，`maxSteps=6`），复用 `UnionAgentTools` 工具：

| 智能体 | 用途 | 工具 |
| --- | --- | --- |
| `union-selector` | 选品推荐 | `queryHotGoods`、`calcCommission` |
| `union-policy` | 政策/结算咨询 | `queryPolicyRule` |
| `union-copywriter` | 文案生成 | `queryGoodsInfo`、`generateCopywriting` |
| `union-compliance` | 合规审核（**敏感工具，触发人工审批**） | `complianceCheck` |
| `union-insight` | 经营洞察 | `queryInsightStats` |

> 注意：`complianceCheck` 标记 `sensitive=true`，调用会走人工审批；`queryInsightStats`/`queryPolicyRule` 等当前返回**示例文本**，非真实业务数据源。

## 六、管理端功能明细（八大分组）

### 6.0 通用约定

> **路径前缀说明**：全局 `server.servlet.context-path=/api`。本章及第七章的管理端路径**省略 context-path**，即表中 `/admin/union/...` 实际为 `/api/admin/union/...`；第八、九章为便于对照外部调用已写全 `/api` 前缀。

- **标准 CRUD 接口**（生成式控制器，每个资源一套）：

  | 方法 | 路径 | 权限 |
  | --- | --- | --- |
  | GET | `/admin/union/{key}/page` | `union:{key}:query` |
  | GET | `/admin/union/{key}/{id}` | `union:{key}:query` |
  | POST | `/admin/union/{key}` | `union:{key}:create` |
  | PUT | `/admin/union/{key}` | `union:{key}:update` |
  | DELETE | `/admin/union/{key}/{id}` | `union:{key}:delete` |

- 写操作附加 `@OperateLog` 操作日志。
- **无批量删除接口**：前端以 `Promise.all` 并发单删过渡（后续可统一补 `/batch`）。
- 页面形态：**维护型**（含 `modules/form.vue`，可增改删）、**只读型**（仅 `index.vue`+`detail.vue`，仅查看/详情）、**特殊型**。

### 6.1 推广管理（2201）

| 页面 | 形态 | 说明与注意 |
| --- | --- | --- |
| 推广链接 `promotion-link` | 维护型 | 转链生成的链接记录；同「推广者+商品+类型」未过期会**复用**（`reused=true`） |
| 推广文案模板 `promotion-template` | 维护型 | 取启用且 `templateType=文本`，按 `priority` 升序、平台精确优先再退化通用；渲染 `{title}/{price}/{commission}` |
| 转链配置 `link-config` | 维护型 | 启用且按 `priority` 升序匹配（平台精确或通用）；控制 `autoSaveProduct`/短链开关/有效期 |
| 转链请求日志 `link-request-log` | 只读型 | 每次转链的入参/结果/失败原因；`source_input` 超 48 字符脱敏 |
| 短链接映射 `short-url-map` | 维护型 | 短码=`base62(雪花ID)`，冲突重试 5 次；有效期：平台返回 > 配置 `shortUrlExpireDays` > 默认 30 天 |
| 推广链接点击明细 `click-tracking` | 只读型 | 点击异步落库 + IP 归属地 + UV 去重（Redis 7 天）+ 原子计数 |

**使用要点**

- 转链输入支持 4 种：商品链接（自动识别平台）、淘口令（含 `￥`，默认淘宝）、商品 ID（需 `platformHint`）、关键词（兜底，需 `platformHint`）。
- 商品已下架 → 转链报 `PRODUCT_NOT_ON_SALE`；配置停用 → `LINK_CONFIG_DISABLED`。
- 短链生成失败**降级为长链**（仅告警），不阻断转链。

### 6.2 商品管理（2202）

## 七、提现与微信支付专项

### 7.1 提现全流程

```text
会员申请 → 校验（起提额/余额/单日累计/归属/收款账号）→ 落单(待审核) → 冻结余额 → 风控自动审核
  ├─ 自动通过 → 审核通过(2)
  ├─ 转人工/降额 → 保持待审核(1) → 管理端人工审核
  └─ 拒绝 → 已驳回(4) + 解冻 + 通知
管理端审核通过 → 打款（两阶段）→ 已打款(3) / 处理中(7) / 打款失败(6)
  ├─ 处理中 → 回调 / 定时查单 / 手动查单 收敛
  └─ 失败 → 重试，达上限自动解冻退回(5)
```

### 7.2 状态机（`union_withdraw_apply.status`）

| 值 | 状态 | 说明 |
| --- | --- | --- |
| 1 | 待审核 | 仅此状态可审核 |
| 2 | 审核通过 | 可打款 |
| 3 | 已打款 | **资金已出账的终态** |
| 4 | 已驳回 | 终态（已解冻） |
| 5 | 已取消 | 终态（已解冻） |
| 6 | 打款失败 | 可重试打款 / 取消 |
| 7 | 打款处理中 | **渠道已受理、资金尚未到账**，须回调/查单收敛，不可直接判成功 |

> `canPay` = 2 或 6（**不含 7**，避免在途重复出账）；`isFinal` = 3/4/5。

### 7.3 两阶段打款（资金安全闸口）

`WithdrawTransferService.startPay` 为**非事务编排**，分三步经 `WithdrawSettlementService` 的短事务落库：

1. **阶段一（短事务）** `markPaying`：CAS 置处理中(7) + 落 `outBillNo`（幂等键，复用申请单号）；
2. **阶段二（事务外）** `WithdrawPayService.pay`：调用渠道（不占数据库连接，超时/失败不回滚「处理中」）；
3. **阶段三（短事务）** 按结果收敛：`convergeSuccess`（扣冻结）/ `keepPaying`（保持 7）/ `convergeFailure`（失败计数、达上限解冻）。

> **为何独立成 Bean**：避免同类方法调用 `@Transactional` 因 Spring 代理失效而不生效。

### 7.4 打款渠道（SPI）

| 渠道 | 条件 | 说明 |
| --- | --- | --- |
| `WechatWithdrawPayChannel` | `zhush.pay.wx.enabled=true` 且 type=3 | 微信 v3 商家转账；单笔限额校验 |
| `BankCardWithdrawPayChannel` | `zhush.pay.wx.bank.enabled=true` 且 type=1 | 微信 V2「企业付款到银行卡」 |
| Mock 兜底 | 无渠道实现时 | **仅非生产**：生产环境无渠道时返回**失败**（不「假成功」） |
| 支付宝 type=2 | — | ⚠️ **未实现**（无渠道） |

### 7.5 回调 / 查单 / 撤销

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 微信回调 | `POST /union/callback/wechat/transfer`（`@IgnoreAuth`，仅 `wx.enabled=true` 注册） | **强制验签解密**，失败返回 500 让微信重试；成功返回 `{"code":"SUCCESS"}` |
| 定时查单 | `wechatTransferQueryJob`（每分钟） | 收敛处理中(7)；超时「待用户确认」发起撤销 |
| 手动撤销 | `POST /admin/union/withdraw/{id}/cancel`（权限 `:pay`） | 仅处理中(7)；**仅渠道确认 `CANCELLED` 才解冻** |
| 手动查单 | `POST /admin/union/withdraw/{id}/requery`（权限 `:pay`） | 对处理中(7)立即查单收敛 |

### 7.6 对账（本地自校准）

`WechatTransferReconcileService` 以「本地单据 + 资金流水」为数据源，**不拉取微信账单**，核对：
已出账=已扣冻结、重复扣款、在途积压（处理中 > 30 分钟）、渠道单号缺失；差异落 `union_wechat_transfer_reconcile`。
**幂等**：同一业务日+差异类型+申请单号仅记一次。

### 7.7 提现配置键

| 配置键 | 含义 | 默认 |
| --- | --- | --- |
| `withdraw.min.amount` | 起提金额 | 10 |
| `withdraw.fee.rate` | 手续费率(%) | 0 |
| `withdraw.tax.rate` | 代扣税费率(%) | 0 |
| `withdraw.max.retry` | 打款最大重试次数 | 3 |
| `withdraw.daily.max.amount` | 单日累计提现上限（0=不限） | 0 |
| `withdraw.auto.audit.enabled` | 风控自动审核 | true |
| `risk.auto.pass.threshold` | 自动通过风险分阈值 | 60 |

### 7.8 ⚠️ 提现/支付注意事项

1. **生产禁 Mock**：`prod` 下无渠道实现时打款返回失败，不会「假成功」；非生产仍可 Mock 跑通。
2. **前端未接入撤销/查单**：后端 `/{id}/cancel`、`/{id}/requery` 已就绪，但前端 `api/union/withdraw.ts` **仅 page/detail/audit/pay**，页面暂无撤销/查单按钮。
3. **前端状态字典缺 7**：`withdraw.ts` 注释与 `WITHDRAW_STATUS_TAG` 仅覆盖 1~6，**处理中(7) 可能显示为 `-`**，需补字典。
4. **对账差异无处置入口**：差异仅落表 + `log.error`，**无查询/标记接口、无告警通道**（PAY-04）。
5. **支付宝提现未实现**：type=2 无渠道（PAY-07）。
6. **银行卡/微信渠道需 fail-fast 凭证**：`wx.enabled=true` 时凭证缺失会导致**启动失败**，属预期保护。
7. 收款账号脱敏存储（前 4 + `****` + 后 4）。

## 十、全局注意事项与风险

### 10.1 路由与菜单

- `sys_menu.path` **必须写相对段**，否则 URL 重复（见 §2.2）；`component` 保持绝对路径。
- 同级拼接后的 `path` **不可重名**：业务组段需避开叶子段（本模块「商品管理」用 `goods` 避开叶子 `product`；「订单管理」用 `orders` 避开叶子 `order`）。
- 菜单脚本幂等，改后重跑即可；`sys_role_menu.id` 取 `menu_id`。

### 10.2 空表 / 全量查询

- 前端分类树等「取全量」场景用 `pageSize=-1`（`PAGE_SIZE_NONE`）；空结果已兜底（`BaseMapperX` 对全量分支空列表 `pageSize` 取 `max(size,1)`），**否则 MyBatis-Flex 会因 `pageSize=0` 抛异常**。

### 10.3 资金与并发

- 余额变更与流水**同事务成对写入**；更新以 `id + version` 为条件，影响 0 行抛并发冲突。
- 提现在途(7)**不可直接判成功**，必须回调/查单收敛；撤销**仅渠道确认 `CANCELLED` 才解冻**。
- 打款失败重试达上限自动解冻退回。

### 10.4 幂等键汇总

| 场景 | 幂等键 |
| --- | --- |
| 商品 | `(platform, outer_product_id)` |
| 订单 | `uk_platform_outer_order` + Redis 锁 |
| 佣金记录 | `uk_order_id` |
| 外部结算 | `settle_status=待结算` 条件更新抢占 |
| 提现打款 | `outBillNo`（复用申请单号） |
| 团队快照 | `member_id + snapshot_date` |
| 对账 | 业务日 + 差异类型 + 申请单号 |

### 10.5 环境与配置

- 生产/测试/docker **缺 `zhush.union.*` 配置** → 短链域名回退 localhost（见 §3.4），上线前必补。
- 定时任务依赖 `zhush.job.enabled=true`。
- 通知仅入库（无 WebSocket）；订单无 MQ（推送+轮询双通道）。
