# 登录与权限系统设计文档

> 适用项目：`zhush-boot4-parent`（Spring Boot 4.1.0 / Java 21 / MyBatis-Flex / Sa-Token / MySQL 8.0+）
>
> 本文记录登录与权限系统的整体方案、表结构、代码实现与联调方式，作为落地过程与后续维护的依据。

---

## 1. 需求与结论

| 需求 | 落地结论 |
| --- | --- |
| 端划分 | 按 URL 前缀划分：管理端 `/admin/**`、会员端 `/member/**` |
| 认证框架 | Sa-Token 多账号体系：`admin` 与 `member` 两套独立登录态 |
| 会员登录 | 微信小程序 `code2Session` 登录，openid 不存在则**静默注册** |
| 会员扩展 | `member_social_user` 通用第三方授权表，预留公众号/开放平台/支付宝/Apple 等 |
| 管理端登录 | 账号密码登录（BCrypt），并**预留第三方登录扩展**（企业微信、钉钉等） |
| 权限模型 | 管理端 RBAC（用户→角色→菜单三级）；会员端无权限，仅登录态 |
| 互相踢下线 | 同账号**同端**登录时踢掉旧会话；不同端（PC/APP/MINI）可共存 |
| 数据库 | MySQL 8.0+，DDL 位于 `./sql/`，本设计文档位于 `./docs/` |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        HTTP 请求                              │
│           /admin/**                     /member/**            │
└───────────────┬─────────────────────────────┬───────────────┘

        ┌───────▼────────────────────────────▼────────┐

        │  1. @IgnoreAuth / 白名单 → 放行               │
        │  2. /admin/** → StpAdminUtil.checkLogin()    │
        │  3. /member/** → StpMemberUtil.checkLogin()  │
        └───────┬────────────────────────────┬─────────┘
                │                             │
   ┌────────────▼───────────┐    ┌────────────▼────────────┐
   │  zhush-module-system   │    │  zhush-module-member     │
   │  AdminAuthController   │    │  MemberAuthController     │
   │  AdminAuthService      │    │  MemberAuthService        │
   │  AdminPermissionService│    │  WxMiniClient(code2Session)│
   │  AdminStpInterfaceImpl │    │                           │
   └────────────┬───────────┘    └────────────┬────────────┘
                │                             │
   ┌────────────▼─────────────────────────────▼────────────┐
   │       MySQL：RBAC 表 + 会员表（MyBatis-Flex）           │
   └────────────────────────────────────────────────────────┘

### 2.1 模块与依赖关系

| 模块 | 职责 |
| --- | --- |
| `zhush-spring-boot-starter-satoken` | 框架层：多账号工具 `StpAdminUtil`/`StpMemberUtil`、`@IgnoreAuth`、拦截器与自动配置 |
| `zhush-spring-boot-starter-mybatis` | 数据层：MyBatis-Flex、多数据源；桥接登录用户 ID 供审计字段填充 |
| `zhush-module-system` | 管理端：RBAC 实体/Mapper、权限服务、`StpInterface` 实现、登录接口 |
| `zhush-module-member` | 会员端：会员实体/Mapper、微信小程序客户端、认证服务、登录接口 |
| `zhush-server` | 启动聚合模块，`spring-boot-maven-plugin:repackage` 打包可执行 jar |

> 依赖方向（关键，避免循环依赖）：
> `mybatis --provided--> satoken --> web`。
> 因此 satoken **不能**反向依赖 mybatis；登录用户 ID 的桥接逻辑放在 mybatis 的 `GlobalFlexAutoConfiguration` 中，通过 `LoginUserContextHolder.setUserIdSupplier(...)` 注入。

## 3. Sa-Token 多账号方案

### 3.1 为什么用多账号（StpLogic）

管理端与会员端是两类完全独立的主体：Token 名、会话、超时、权限模型都不同。Sa-Token 的多账号体系通过为每个账号类型创建独立的 `StpLogic` 实例实现隔离：

```java
// StpAdminUtil（type = "admin"，含权限方法）
public static final StpLogic STP_LOGIC = new StpLogic(LoginTypeConstants.ADMIN);

// StpMemberUtil（type = "member"，无权限方法）
public static final StpLogic STP_LOGIC = new StpLogic(LoginTypeConstants.MEMBER);
```

`new StpLogic(TYPE)` 在构造时会自动注册到 `SaManager`，两套登录态彼此隔离，互不影响。

### 3.2 常量约定

| 常量类 | 值 |
| --- | --- |
| `LoginTypeConstants` | `ADMIN = "admin"`、`MEMBER = "member"` |
| `DeviceTypeConstants` | `PC`、`APP`、`MINI`（用于设备维度的会话管理） |

### 3.3 拦截器鉴权（`SaTokenConfigure`）

- `@IgnoreAuth`（方法或类级）→ 直接放行；
- 内置白名单：`/admin/auth/login`、`/admin/auth/social-login`、`/member/auth/login`、`/member/auth/wx-mini-login`、`/error`、`/doc.html`、`/swagger-ui/**` 等；
- `/admin/**` → `StpAdminUtil.checkLogin()`；`/member/**` → `StpMemberUtil.checkLogin()`；
- 细粒度权限由业务接口上的 `@SaCheckPermission(type = "admin")` 等注解按需校验。

白名单前缀可通过配置 `zhush.security`（`SecurityProperties`）扩展：`admin-prefix`、`member-prefix`、`ignore-paths`。

## 4. 数据库设计

DDL 文件：`./sql/01_admin_rbac.sql`、`./sql/02_member.sql`。

统一约定：
- 主键 `id BIGINT`，应用层雪花算法生成；
- 公共字段 `create_by / create_time / update_by / update_time / is_delete`，对应 `com.zhush.common.entity.BaseEntity`；
- 逻辑删除 `is_delete`（0 正常 / 1 删除），唯一索引带 `is_delete` 以兼容逻辑删除后重复写入；
- 字符集 `utf8mb4`，引擎 `InnoDB`。

### 4.1 管理端 RBAC（`01_admin_rbac.sql`）

| 表 | 说明 | 关键字段 / 索引 |
| --- | --- | --- |
| `sys_admin_user` | 管理员用户 | `username`（BCrypt 密码）、`status`、`dept_id`(预留)；`uk_username(username,is_delete)` |
| `sys_role` | 角色 | `code`（如 `super_admin`）、`data_scope`(预留)；`uk_code(code,is_delete)` |
| `sys_menu` | 菜单/权限（目录/菜单/按钮三级） | `parent_id`、`type`、`permission`（如 `system:user:add`） |
| `sys_admin_user_role` | 管理员-角色关联 | `user_id`、`role_id` |
| `sys_role_menu` | 角色-菜单关联 | `role_id`、`menu_id` |
| `sys_social_user` | 管理端第三方绑定（预留） | `social_type`(WECOM/DINGTALK...)、`open_id`；`uk_type_openid` |

RBAC 关系：`用户 --n:n-- 角色 --n:n-- 菜单`。权限判定时聚合用户所有角色的菜单 `permission` 集合。

初始化数据：内置管理员 `admin`（BCrypt 口令 `123456`）、角色 `super_admin`，并建立关联。**super_admin 拥有全部权限**（见 §5.1）。

### 4.2 会员端（`02_member.sql`）

| 表 | 说明 | 关键字段 / 索引 |
| --- | --- | --- |
| `member_user` | 会员用户 | `mobile`、`password`(可空)、`nickname`、`status`、`register_type`；`idx_mobile` |
| `member_social_user` | 会员第三方授权（通用） | `social_type`(WECHAT_MINI/WECHAT_MP/ALIPAY/APPLE...)、`open_id`、`union_id`、`session_key`；`uk_type_openid`、`idx_union_id` |

会员端**无 RBAC**，仅登录态。`member_social_user` 为通用结构，新增第三方渠道只需新增 `social_type` 值，无需改表。

## 5. 管理端实现（zhush-module-system）

### 5.1 权限服务 `AdminPermissionService`

- `getRoleCodeList(userId)`：查用户所有角色 `code`；
- `getPermissionList(userId)`：
  - 若角色含 `super_admin` → 直接返回 Sa-Token 通配符 `["*"]`（拥有一切权限）；
  - 否则：用户角色 → `sys_role_menu` → `sys_menu`，聚合非空 `permission` 去重返回。

### 5.2 `AdminStpInterfaceImpl implements StpInterface`

Sa-Token 权限数据源。按 `loginType` 区分账号体系，仅对 `admin` 类型返回权限/角色，`member` 返回空集合：

```java
if (!LoginTypeConstants.ADMIN.equals(loginType)) {
    return Collections.emptyList();
}
// getPermissionList / getRoleList → 调用 AdminPermissionService
```

### 5.3 登录服务 `AdminAuthService`

- `login(reqVO)`：按 `username` 查用户 → 校验状态 → `BCrypt.checkpw` 校验密码 → `doLogin`；
- `doLogin(user, device)`：**先 `StpAdminUtil.logout(userId, device)` 踢同端旧会话**，再 `StpAdminUtil.login(userId, device)`，回写 `login_ip`/`login_date`；
- `socialLogin(reqVO)`：**预留**第三方登录（企业微信等），当前抛出 `SYSTEM_CONFIG_MISSING` 提示未配置，接入时补齐渠道换取 openid → 查 `sys_social_user` → 绑定/登录；
- `getUserInfo()`：返回当前登录管理员信息 + 角色/权限集合。

### 5.4 接口 `AdminAuthController`（`/admin/auth`）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/admin/auth/login` | `@IgnoreAuth` | 账号密码登录 |
| POST | `/admin/auth/social-login` | `@IgnoreAuth` | 第三方登录（预留） |
| POST | `/admin/auth/logout` | 需登录 | 注销 |
| GET | `/admin/auth/user-info` | 需登录 | 当前管理员信息 |

## 6. 会员端实现（zhush-module-member）

### 6.1 微信小程序客户端 `WxMiniClient`

- 配置：`WxMaProperties`（`@ConfigurationProperties("zhush.member.wx-mini")`，含 `appId`/`appSecret`）；
- `code2Session(code)`：调用 `https://api.weixin.qq.com/sns/jscode2session`（hutool `HttpUtil.get` + `JSONUtil.parseObj`），解析 `openid`/`session_key`/`unionid`；`errcode != 0` 抛 `MemberErrorCode.WX_MINI_LOGIN_FAIL`。

### 6.2 认证服务 `MemberAuthService`

- `wxMiniLogin(reqVO)`（`@Transactional`，静默注册）：
  1. `code2Session` 换取 openid；
  2. 按 `(WECHAT_MINI, openid)` 查 `member_social_user`；
  3. **不存在** → 新建 `member_user`（昵称"微信用户"）+ 绑定 `member_social_user`，标记 `newRegister = true`；
  4. **已存在** → 刷新 `session_key` / `unionId`；
  5. 校验会员状态 → `doLogin`（同端互踢）→ 返回 token 与 `newRegister`。
- `passwordLogin(reqVO)`：按 `mobile` 查会员 → BCrypt 校验 → `doLogin`；
- `logout()` / `getUserInfo()`：注销与当前会员信息。

### 6.3 接口 `MemberAuthController`（`/member/auth`）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/member/auth/wx-mini-login` | `@IgnoreAuth` | 微信小程序登录（静默注册） |
| POST | `/member/auth/login` | `@IgnoreAuth` | 账号密码登录 |
| POST | `/member/auth/logout` | 需登录 | 注销 |
| GET | `/member/auth/user-info` | 需登录 | 当前会员信息 |

## 7. "互相踢下线"实现

需求：同账号在**同一端**再次登录，踢掉该端的旧会话；不同端可并存（如 PC 与 APP 同时在线）。

实现方式（管理端 / 会员端一致）——登录前按设备踢旧会话：

```java
StpXxxUtil.logout(userId, device);  // 踢掉该用户在该 device 的旧登录
StpXxxUtil.login(userId, device);   // 建立新会话
```

- 依赖 Sa-Token 的设备维度会话管理（`device` = `PC`/`APP`/`MINI`）；
- 会员端小程序默认 `device = MINI`，管理端 Web 默认 `device = PC`；
- 若需"全端唯一登录"，将策略改为 `StpXxxUtil.logout(userId)`（不带 device）即可。

## 8. 登录用户上下文桥接（审计字段）

MyBatis-Flex 的插入/更新监听器需要"当前登录用户 ID"以填充 `create_by`/`update_by`。为避免 satoken 反向依赖 mybatis 造成循环，桥接逻辑放在 mybatis starter 的 `GlobalFlexAutoConfiguration`：

```java
LoginUserContextHolder.setUserIdSupplier(() -> {
    Long adminId = StpAdminUtil.getLoginIdDefaultNull();
    if (adminId != null) { return adminId; }
    return StpMemberUtil.getLoginIdDefaultNull();
});
```

即优先取管理端登录 ID，其次会员端；无人登录返回 `null`（如系统内部任务）。

## 9. 关键配置示例（application.yml）

```yaml
zhush:
  security:
    admin-prefix: /admin/**
    member-prefix: /member/**
    ignore-paths:
      - /admin/auth/captcha   # 按需追加白名单
  member:
    wx-mini:
      app-id: your-appid
      app-secret: your-secret

sa-token:
  token-name: satoken
  timeout: 2592000          # 30 天
  is-concurrent: true       # 允许同账号多端并发登录
  is-share: false           # 每次登录产生新 token（配合同端互踢）
```

> `is-concurrent: true` + `is-share: false` 是"多端并存 + 同端互踢"的基础前提。

## 10. 落地与联调步骤

1. **建库建表**：在 MySQL 8.0+ 依次执行 `sql/01_admin_rbac.sql`、`sql/02_member.sql`；
2. **配置**：填写数据源、`zhush.member.wx-mini` 小程序 appId/secret、`sa-token` 参数；
3. **编译**：`mvn -DskipTests install`（已验证 BUILD SUCCESS）；
4. **启动**：运行 `zhush-server`；
5. **验证管理端**：
   - `POST /admin/auth/login` → `{"username":"admin","password":"123456"}` 取得 token；
   - 携带 token 请求 `GET /admin/auth/user-info`，应返回角色 `super_admin` 与权限 `["*"]`；
6. **验证会员端**：
   - `POST /member/auth/wx-mini-login` → `{"code":"<小程序wx.login的code>"}`，首次返回 `newRegister=true`；
   - 再次同 openid 登录 `newRegister=false`；
7. **验证互踢**：同账号同端二次登录后，用旧 token 请求受保护接口应返回"已在别处登录/未登录"。

## 11. 构建过程记录（问题与修复）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `cyclic reference: mybatis --> satoken --> mybatis` | 误在 satoken pom 增加对 mybatis 的依赖；而 mybatis 已 `provided` 依赖 satoken | 撤销 satoken→mybatis 依赖，桥接逻辑移入 mybatis 的 `GlobalFlexAutoConfiguration`（改用 `StpAdminUtil`/`StpMemberUtil`） |
| `mvn` ExitCode=1 但实际成功 | PowerShell 把 mvn stderr 警告当错误 | 以日志中的 `BUILD SUCCESS`/`BUILD FAILURE` 为准，不看 exit code |
| repackage 阶段 `数据错误(循环冗余检查)` | 本地 jar/临时产物一次性文件损坏（CRC），非依赖循环 | 清理后离线重建（`-o`），恢复 `BUILD SUCCESS` |
