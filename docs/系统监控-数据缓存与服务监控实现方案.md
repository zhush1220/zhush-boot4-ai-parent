## 三、数据监控（Druid）设计

### 3.1 安全策略（核心）
**采用「关闭 Druid Web + 后端读取统计 + 授权接口输出」方案**，彻底消除 `/druid/*` 暴露风险：

1. **关闭 StatViewServlet Web 访问**：`application-dev.yaml` 中将
   ```yaml
   spring.datasource.druid.stat-view-servlet.enabled: false
   ```
   仅保留 `filter.stat` / `filter.wall` 的**统计采集**（与 Web 展示相互独立，关闭 Web 不影响统计）。
2. 后端通过 `com.alibaba.druid.stat.DruidStatManagerFacade.getInstance()` 读取 `StatFilter` 采集的统计（数据源 / SQL / URI / Wall / 会话），全部为**内存态只读**。
3. 前端通过 `/admin/system/monitor/druid/*` 授权接口展示，统一走 Sa-Token 管理端登录态 + `@SaCheckPermission`。
4. 移除内置账号密码配置、`allow/deny`、`reset-enable` 等敏感项（若仅需关闭 Web，则 `enabled=false` 即可一并使 `login-username/password` 失效）。

**不推荐 iframe 内嵌 `/druid/index.html`**：其内置 HTTP Basic/session 登录与 Sa-Token 鉴权难以复用；密码一旦出现在前端即泄露；且 `allow` 为空时人人可访问。若确有可视化诉求，后续可再将关键报表自绘，而非暴露原生页。

### 3.2 后端接口（`AdminDruidMonitorController`）
基路径 `/admin/system/monitor/druid`，全部 `@SaCheckPermission(type=CommonConstant.TYPE, value="system:monitor:druid:query")`，重置接口单独授权 `system:monitor:druid:reset`+`@Idempotent`。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/datasource` | GET | 数据源监控列表（连接数/活跃/空闲/提交/回滚/最大并发等） |
| `/sql` | GET | SQL 监控分页（SQL 文本、执行次数、行数、耗时、命中率）、支持 `sql` 关键词过滤 |
| `/uri` | GET | URI 访问监控（请求次数、并发、耗时） |
| `/wall` | GET | Wall 防火墙统计（拦截数、黑名单、SQL 注入命中） |
| `/session` | GET | 会话监控（可关闭，默认不启用） |
| `/reset` | POST | 重置统计（`@Idempotent`，权限 `system:monitor:druid:reset`） |

Service：`DruidMonitorService`，用 `DruidStatManagerFacade` 取 `getDataSourceStatList()`、`getSqlStatMap()`、`getUriStatMap()`、`getWallStatMap()`、`resetAllStat()`。分页在内存完成（统计数据量通常有限，`PAGE_SIZE_NONE=-1` 返回全部）。返回 `PageResult` 或 `List<Map<String,Object>>`，前端映射为表格。

### 3.3 前端
- `views/monitor/druid/index.vue`：顶部 `usage 概要卡`（数据源连接 / 慢SQL数 / 防注入拦截数）+ 下方 Tab：**SQL 监控**、**URI 监控**、**Wall**。复用 job 的列表区布局（刷新/密度/列设置）。
- 搜索：SQL 监控提供关键词输入（`useVbenForm` inline），过滤 SQL 文本。
- 按钮：`重置统计`（`v-access:code="'system:monitor:druid:reset'"`，需二次确认）。
- `data.ts`：`useDruidSearchSchema`、`useDruidSqlColumns`（列配置单源驱动）。

## 四、缓存监控（Redis）设计

### 4.1 能力
查看 Redis 缓存 **列表**、**详情**、**删除**、**搜索（pattern）**。

### 4.2 后端接口（`AdminCacheMonitorController`）
基路径 `/admin/system/monitor/cache`，查询授权 `system:monitor:cache:query`，删除授权 `system:monitor:cache:delete`。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/info` | GET | Redis 实例信息：版本、运行模式、内存（used/total/frag）、连接数、命中率、keyspace |
| `/page` | GET | key 分页列表：入参 `pattern`（模糊搜索，默认 `*`）、`pageNum`/`pageSize`；返回 `PageResult<{key,type,ttl,size}>` |
| `/detail` | GET | key 详情：入参 `key`（**query 参数**，避免 path 编码/特殊字符问题）；返回 `{key,type,ttl,size,encoding,valuePreview}` |
| `/delete` | DELETE | 删除 key：入参 `key`（query 参数）；`@Idempotent`；返回删除数量 |

Service：`CacheMonitorService`，注入 `StringRedisTemplate`。
- **列表**：用 `scan(cursor, ScanOptions.match(pattern).count(200))` 迭代（**禁用 `keys`**，避免阻塞 O(N)），最多收集 `MAX_SCAN_KEYS=10000`，内存分页；对每个 key 取 `type`/`ttl`/`strlen`(或 `debug object` 的 serializedlength)。
- **详情**：按 `type` 用 `type(key)` 判断，再取 `range/list`(list)、`hashGet`/`entries`(hash)、`members`(set)、`zrangeWithScores`(zset)、`get`(string)；value 统一做 UTF-8 可读化 + **截断（如 1000 字符）** 并给出 `size`，避免大 key 撑爆响应。
- **删除**：`delete(key)`，返回 `Long`；命中黑名单前缀则抛 `MONITOR_CACHE_KEY_FORBIDDEN`。

### 4.3 安全策略
1. **删除权限独立**：`system:monitor:cache:delete` 不与查询权限合并，仅授权运维/管理角色。
2. **关键前缀保护**：`BLOCKED_KEY_PREFIXES`（可配，默认含 `sa:`、`refresh:`、`login:` 等认证/会话前缀）命中则拒绝删除并提示 `MONITOR_CACHE_KEY_FORBIDDEN`；**禁止一键清空**。
3. **SCAN 而非 KEYS**：防止阻塞与大数据量卡顿。
4. **值预览截断**：只读安全，避免敏感/大内容一次性回传。

### 4.4 前端
- `views/monitor/cache/index.vue`：搜索区（`pattern` 输入 + 查询/重置）+ 分页表格（key/type/ttl/size）+ 操作列（`详情`、`删除`，`v-access:code` 控制）。
- `modules/detail.vue`：`useVbenModal` 弹框，展示 type/ttl/size/encoding 与 value 预览（超长显示"已截断"）。
- `data.ts`：搜索 schema + 列配置。
- 详情/删除接口以 `key` 作为 **query string** 传递（后端 `@RequestParam`），前端 `encodeURIComponent(key)`。

## 五、服务监控（CPU/内存/服务器/JVM/磁盘）设计

### 5.1 技术选型
**主选：JDK 内建 MXBean + `java.nio.file.FileStore`，零新增依赖**（无需引入 oshi）。
- CPU：`com.sun.management.OperatingSystemMXBean.getCpuLoad()`（系统整体负载）、`getAvailableProcessors()`、`getSystemLoadAverage()`。
- 内存：`OperatingSystemMXBean.getTotalMemorySize()/getFreeMemorySize()`（物理内存）。
- JVM：`Runtime`（总/可用/最大）、`MemoryMXBean`（堆/非堆/已用）、`GarbageCollectorMXBean`（GC 次数/耗时）、`ClassLoadingMXBean`、`ThreadMXBean`、`RuntimeMXBean.getUptime()`。
- 服务器/OS：`System.getProperty(os.name/version/arch/user.dir/java.version)`、`InetAddress.getLocalHost()`（主机名/IP）、`RuntimeMXBean`（运行时长、启动时间、输入参数）。
- 磁盘：`File.listRoots()` + `FileStore`（总/可用/已用、挂载点、文件系统类型）。

> 备选：若需 CPU 历史曲线/磁盘 IO 更精确，可引入 `oshi-core`（需在 `zhush-dependencies/pom.xml` 增加版本管理并在 module-system 引入）。本期以 JDK 内建为主，避免依赖膨胀。

### 5.2 后端接口（`AdminServerMonitorController`）
| 接口 | 方法 | 说明 |
|---|---|---|
| `/info` | GET | 聚合返回全部：CPU、内存、JVM、系统/OS、磁盘（一次渲染，前端提供刷新） |

- 授权 `system:monitor:server:query`。
- 返回值：`MonitorServerVO` 聚合对象，含：
  - `cpu`：核数、系统负载、使用率（0~100，首次采样可能为 `-1`，前端显示"计算中"）；
  - `memory`：总量/已用/可用/使用率；
  - `jvm`：堆/非堆/已用/最大、GC 次数/耗时、类加载数、线程数、运行时长；
  - `sys`：OS 名/版本/架构、主机名、IP、Java 版本、启动时间；
  - `disks`：数组（每分区：盘符/挂载点、文件系统、总量/可用/已用/使用率）。

Service：`ServerMonitorService`，按上述 MXBean/FileStore 采集。

### 5.3 前端
- `views/monitor/server/index.vue`：整体概览卡片 + 进度条（CPU/内存/堆染色区分），磁盘分区列表卡片 + 系统/JVM 信息卡片；顶部「刷新」按钮（**仅手动刷新，不做自动轮询**）。
- 实时折线（本期实现）：引入 `echarts`（workspace catalog 已有 `^6.1.0`），在 `apps/web-antdv-next/package.json` 增加该依赖后，CPU / 内存 使用率用 `echarts` 折线图展示。按需引入（`echarts/core` + `LineChart` + 必要组件/渲染器），并注册中文语言包[^1]，控制体积。

[^1]: ECharts 原生默认英文；如需中文化需 `import 'echarts/i18n/langZH'` 并 `registerLocale('ZH', langZH)`。

1. **Druid 展示方式**：采用「关闭 Web + 后端统计 + 前端自绘」（不暴露 `/druid/*`）。
