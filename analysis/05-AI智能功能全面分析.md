## 一、总体结论

**一句话：底座强、业务面窄。** 系统具备自研的、机制完整的智能体（Agent）运行底座，而非「调一次大模型」的封装；但真正端到端可用的业务能力只有「对话 + 工具调用 + 文档生成/解析」，RAG/知识库、图像视频生成、C 端接入、按人配额四项均未开工。

| 维度 | 评级 | 依据 |
|---|---|---|
| 架构完整度 | ★★★★☆ | ReAct、多模型池、工具桥接、审批、计量、审计、会话七要素齐备，且均实现「DB 优先 + yaml 回退」双通道降级 |
| 代码规模 | — | `starter-agentscope` 60 文件 / 4,087 行；`zhush-module-ai` 80 文件 / 5,250 行；`starter-file` 15 文件 / 1,132 行 |
| 业务可用性 | ★★☆☆☆ | 仅对话与文本域产物能力可用；union 5 个业务智能体中 3 个工具为写死演示数据 |
| 安全治理 | ★★☆☆☆ | 机制层（敏感词分级 / 双路线审批 / SSRF 白名单）优秀；接入层（接口权限点、会话归属校验）存在明确缺口 |
| 成本可控性 | ★☆☆☆☆ | **有计量、无预算**：Token 与成本已入库，但无按人配额、无限流组件、AI 接口未接入既有幂等能力 |
| 可扩展性 | ★★★☆☆ | 三处单实例内存态（`harnessCache` / `pendingConfirms` / `AgentResumeChannels`），多副本部署会丢续跑 |

## 三、已交付能力矩阵

### 3.1 智能体运行时 ✅

- 统一门面 `AgentTemplate`：`chat / stream / chatAsync / callOnce / resumeConfirm / newSession / clearSession / evictAgentCache`。
- `DefaultAgentTemplate.buildHarness`：装配 `HarnessAgent`（sysPrompt + toolkit + `maxIters`），实例按 `name#native` / `name#legacy` 双变体缓存，避免上下文装配方式互相污染。
- 事件流：`STARTED / TEXT_DELTA / TOOL_CALLED / TOOL_RESULT / APPROVAL_REQUIRED / FINISHED / ERROR`；`MODEL_CALL_END` 仅累加不外发。
- 工具结果转发：聚合 `TOOL_RESULT_TEXT_DELTA` + `TOOL_RESULT_END` 为一次性 `AgentToolResultEvent(id, name, result, ok)`，结果文本截断 4000 字符；`TOOL_CALLED` 事件只带工具名、**不带入参**（审批事件 `APPROVAL_REQUIRED` 则按设计携带入参供审批人核阅）。
- 会话上下文：`SessionContextResolver` SPI（starter 侧 `DefaultSessionContextResolver` 为匿名兜底，`zhush-module-ai` 的 `AiSessionContextResolver` 从 Sa-Token 解析 admin/member）产出 `AgentContext{tenantId, userId, userType, nickname}`，在 `DefaultAgentTemplate` 的 chat/stream/事件/审批五处贯通。**但工具方法签名仍拿不到该上下文**（`ReflectiveAgentTool` 只反射 LLM 入参，全仓无 `AgentContextHolder`）。

### 3.2 多模型与动态配置 ✅

- 三供应商：`dashscope` / `openai`（兼容 DeepSeek 等） / `ollama`，见 `DefaultModelFactory`；新增供应商仅需实现 `ChatModelFactory`。
- 解析顺序：**DB 启用态模型池 → yaml `zhush.agentscope.models` → `type:model` 裸解析**，见 `AgentModelResolver.resolve/resolveDefaultCode/resolvePricing`。
- API Key：`ai_model.api_key` AES 密文存储、接口只回掩码、读取时 `AiModelCipher.resolve` 支持 `${ENV}` 占位展开。
- 三级缓存刷新：本实例事件 → Redis pub/sub 广播 → 定时兜底（默认 300s），并联动 `evictAllAgentCache()`；停用被引用模型有阻断校验。

### 3.3 工具与业务智能体 ⚠️ 半完成

- 最小暴露原则：`@AgentTool` 扫描入注册表，`agent_definition.tool_names` 为空即**零工具**（`DefaultToolkitRegistry`）——安全默认值正确，但意味着「不配 = 没有能力」。
- DB seed 智能体：`ai-chat`（已配 `["generateDocument","parseDocument"]`、`max_steps=8`）、`ai-translator`、`ai-summary`（后两者无工具）。
- 代码声明智能体：union 5 个（选品 / 政策 / 文案 / 合规 / 洞察）。
- **工具真实度**：6 个 union 工具中 `queryHotGoods`、`queryGoodsInfo` 真实查库，`calcCommission` 真实计算；**`queryPolicyRule`、`generateCopywriting`、`queryInsightStats` 返回写死文本**（`UnionAgentTools` L93 / L107 / L131），`complianceCheck` 为关键词启发式判断。

### 3.4 对话产物能力（文本域多能力，本期新交付）✅ 待运行验证

- 生成：Markdown → **docx（POI 5.5.1 XWPF）** / **pdf（OpenPDF 2.0.3，CJK 用 `STSongStd-Light` + `UniGB-UCS2-H` 非嵌入，零字体文件依赖）** → `FileClient.upload` → `FileArtifact{type, format, name, url, size}`（`type` 预留 image/video 给多模态；`size` 取 `FileUploadResult.getSize()`，前后端结构一致）。渲染器为自研 `MarkdownLiteParser`（六类块 HEADING/PARAGRAPH/CODE/QUOTE/LIST/TABLE），未引入方案备选 flexmark；**无 IMAGE 块**，故文档内容暂不能内嵌图片。入参侧有 `MAX_CONTENT_CHARS=200_000` 截断。
- 解析：`parseDocument` 复用 `DocParseService`（Tika 文本 + 内嵌图片上传 + HTML 组装），返回给 LLM 的文本受 `MAX_PARSE_CHARS=6_000` 截断并带 `truncated` 标记；只接受 `fileUrl`（方案写的 `fileId` 入口未实现）。
- 交付双通道：流式中 `TOOL_RESULT` → 前端提取 `artifact` 渲染下载卡片；`FINISHED` 时写入 `ai_chat_message.attachments`（JSON）供历史同源回显。
- 旁路：`POST /admin/ai/agent/export` 不经大模型、零 Token，同步返回 `Result<FileArtifact>`（下载外链）。
- 归属留痕：**会话头**写入侧已带 `userId/userType`（`AgentChatService.ensureSessionRow` L249-250，仅新建会话时写入；`ai_chat_message` 本身无归属列，靠 `sessionId` 关联），审批记录同样落审批人 ID —— 但读取侧仍不校验（见 S2）。
- 设计取舍：`ReflectiveAgentTool` 仅按 LLM 入参反射调用、**拿不到 sessionId**，故产物不在工具内直写库而走事件流提取；代价是 `AgentToolResultEvent` 无审计分支，**产物 URL 不进 `agent_audit_log`**。

### 3.5 安全治理 ✅ 机制完备

- 敏感词三级：`level` 1-提示 / 2-审批 / 3-拦截，`match_type` 支持 `tool_name` / `content` / `both`，命中取最高级；yaml 关键词回退按审批级处理（保持存量语义）。
- 审批双路线：路线 A 工具层 `ToolResultBlock.suspended`（默认）；路线 B 权限层 `REQUIRE_USER_CONFIRM` + `enablePendingToolRecovery(true)` + `stopOnReject(true)`，需 `native-state.enabled` **且** `safety.native-confirm` 同时开启（互斥设计，防双门禁）。
- 续跑幂等：`agent_approval.resumed` 列 CAS `0→1` 作幂等闸门，事务提交后（`runAfterCommit`）触发 `resumeNative`，防跨线程读未提交快照。
- 降级策略：无 Redis 时 `NullToolApprovalHandler` 放行，可配 `fail-on-approval-store-unavailable=true` 转 fail-fast。
- 文件取回 SSRF 防护：仅允许 `FileStorageProperties` 中**已启用平台 domain 前缀**的 URL，相对路径剥离 `/files/` 前缀后按 `local.base-path` 解析并 `startsWith` 防目录穿越，不跟随重定向、校验 `max-size`。

### 3.6 计量、成本与审计 ✅（有计量无预算）

- `TokenUsageAccumulator` 逐次累加 → `AgentFinishedEvent(totalTokens/cachedTokens/model)` → `AgentUsageEventListener` 写 `agent_token_usage`。
- 并发写法正确：**DB 侧原子自增**（先 UPDATE，0 行则 INSERT，撞唯一键回退累加），适配事件异步分发；聚合行只增不删（`is_delete` 参与唯一键）。
- 成本：按 `ai_model.input_price/output_price` 折算，缺价或 `cost-enabled=false` 记 0（明确「只计量不计费」）。
- 审计：`agent_audit_log` 落 STARTED/FINISHED/TOOL_CALLED/ERROR/APPROVAL，`traceId` 取事件携带值 → 线程上下文 → `"N/A"`（SkyWalking 集成）。

### 3.7 会话与记忆 ⚠️

- 双轨存储：旧会话每轮 `toMsgs` **全量重发历史**（`RedisAgentSessionStore`，TTL 24h）；新会话可切 `RedissonAgentStateStore` 作运行态唯一事实源。
- **已知上下文缺陷**：`toMsgs` 仅重建 `user/assistant`，工具/系统消息不重建（源码注释「避免破坏消息配对」）→ 旧路径下多轮工具轨迹丢失，长对话成本随轮次线性上涨。

## 六、权限与会话安全问题（本次重点发现）

> 计数方式：逐个 Controller 统计 `@(Get|Post|Put|Delete)Mapping` 与 `@SaCheckPermission`。

| Controller | 接口数 | 权限注解 | 判定 |
|---|---|---|---|
| `AiModelController` | 9 | 9 | ✅ |
| `AiSensitiveWordController` | 7 | 7 | ✅ |
| `AgentApprovalController` | 3 | 3 | ✅ |
| `AgentUsageController` | 3 | 3 | ✅ |
| **`AgentChatController`** | 9 | **0** | 🔴 对话/续跑/会话读删全开放 |
| **`AgentDefinitionController`** | 6 | **0** | 🔴 增删改智能体定义无校验 |
| **`AgentLogController`** | 2 | **0** | 🟠 审计日志可被任意管理员读 |
| **`AgentToolController`** | 1 | **0** | 🟡 工具清单泄露（暴露内部能力名） |
| **`AgentExportController`** | 1 | **0** | 🟡 文件生成接口可被刷 |

`sys_menu` 已入库 **21 个** AI 权限点，代码实际校验 **13 个**，未校验清单：`agent:definition:create` / `agent:definition:update` / `agent:definition:delete` / `agent:log:list` / `agent:tool:list` / `ai:session:list` / `ai:session:delete`（另有 `ai:assistant` 为菜单型）。

### S1｜智能体定义可被任意已登录管理员改写 🔴

`AgentDefinitionController` 的新增/编辑/删除无权限注解，而对应权限点已在菜单中存在。影响面：任何管理员可改 `system_prompt`（注入）、改 `tool_names`（给智能体挂上敏感工具）、改 `model`（指向未授权模型）——**等价于绕过敏感词库与审批配置的治理设计**。

### S2｜会话归属仅由前端过滤（IDOR 链）🔴

`AgentChatService.sessionPage()` 只按 `query.userId` 条件过滤，**服务端不默认收敛为当前登录人**；前端「我的会话」靠 `views/ai/assistant/index.vue:94` 主动传 `userId` 才成立。更关键的是 `sessionMessages(sessionId)`、`deleteSession(sessionId)`、`renameSession(...)` **完全没有归属校验**。

- 攻击链：`GET /session/page`（不传 userId → 全量会话含 sessionId）→ `GET /session/{id}/messages` → 读取任意用户对话全文（含上传附件名与 URL）。
- 现状缓解：仅 Sa-Token 登录态（`/admin/**` 前缀拦截）；`AiSessionContextResolver` 已具备区分 admin/member 的能力，但未被这些查询路径使用。
- 对照要求：`docs/对话框自然语言多能力任务实现方案.md` 已明确要求「产物按会话/租户隔离，禁止跨用户读取附件 URL 猜测」；`docs/union/17-已实现功能总览与使用手册.md` 列明本仓库已有约定「会员端所有接口强制当前登录维度 + 归属校验」。**两个约定在 AI 模块均未落地：代码中不存在任何会话归属断言方法（全仓检索 `assertSessionOwner` / `Owner(` 零命中）。**

### S3｜对话与导出接口无幂等、无限流、无配额 🔴

- `starter-protection` 提供的是 **幂等**能力（`@Idempotent` + 切面 + 用户维度解析，7 个类），**全仓无 RateLimiter 实现**；AI 模块对二者引用数为 **0**。
- 叠加「无按人配额」：`agent_token_usage` 维度仅到 `(日期, 租户, agent)`，任何已登录账号可无限刷 `chat/stream`，单次 `max_steps=8` 意味着一条消息最多放大 8 次模型调用。
- 配额预留位已存但空转：`AiErrorCode` 的 `MODEL_QUOTA_EXCEED` / `CONVERSATION_LIMIT_EXCEED` / `MESSAGE_TOO_LONG` 三码**全仓零引用**（死码），印证「码先占位、校验未写」。

### S4｜移动端复用管理端接口 🟠

`zhush-admin-uni/src/api/ai.ts` 与 `agent.ts` 直接调 `/admin/ai/agent/*`、`/admin/ai/*`。C 端一旦以此形态上线，用户将持有管理员登录态；`/member/ai/agent/*` 至今**不存在任何 Controller**。

### S5｜既有正向实践（应保留）✅

工具调用/工具结果事件不外发入参（但 `APPROVAL_REQUIRED` 按设计携带 `arguments` 以供人工核阅）；`parseDocument` 有 SSRF 白名单与目录穿越防护；审批通过/驳回有幂等状态判断与 CAS 闸门；`truncateText(..., 4000)` 限制事件负载。

## 七、功能缺口清单（分级）

| 级别 | 缺口 | 证据 | 影响 |
|---|---|---|---|
| 🔴 | 会员端（C 端）AI 接口未落地 | `zhush-module-ai/controller` 下仅 `admin` 子包 | C 端功能无法上线，只能借道管理员身份 |
| 🔴 | 无按人配额 / 预算 | 表结构无 user 维度；全仓无限流组件 | 成本不可控，无法做会员权益差异化 |
| 🔴 | RAG / 知识库零实现 | 全库仅 3 个占位错误码 `KNOWLEDGE_NOT_FOUND` / `KNOWLEDGE_DOC_PARSE_FAIL` / `EMBEDDING_FAIL`，无 embedding/向量/检索代码 | 政策问答只能靠 prompt 与硬编码文本，答案无出处 |
| 🟠 | union 3 个工具返回写死数据 | `UnionAgentTools` L93/L107/L131 | 演示可过、真实业务不可信 |
