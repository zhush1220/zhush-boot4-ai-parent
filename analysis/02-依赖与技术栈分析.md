## 二、BOM 治理方式评价

**做得好的**
- 版本唯一来源：`zhush-dependencies` 集中 properties + dependencyManagement，业务模块零 version 声明
- `flatten-maven-plugin` + `${revision}`：CI 友好版本，发版只改一处
- 对不兼容 Boot 4 的组件采用「排除 + 替换」策略（knife4j 排除旧 springdoc），而非硬升级
- Boot 4 专属 starter 正确选型：`sa-token-spring-boot4-starter`、`druid-spring-boot-4-starter`、`mybatis-flex-spring-boot4-starter`

**需要改进的**
1. ~~x-file-storage 缺版本管理~~（本次已修复）——反映 BOM 条目缺少「属性 ↔ 托管条目」一致性检查，建议引入 `maven-enforcer-plugin` 的 `dependencyConvergence` / `requireUpperBoundDeps` 规则兜底
2. 根 POM 定义 `<repositories>` 与 `settings.xml` mirror 并存（构建时产生镜像覆盖告警），二选一更干净
3. `hutool-all` 全量引入（约 4MB），如关注体积可按需换 hutool-core + 单模块
4. WxJava 5 个 artifact 全部托管但当前仅 member 用到 miniapp/mp，pay/cp/open 属预留

## 三、Spring Boot 4 兼容性要点（已踩过的坑）

| 坑 | 表现 | 项目对策 |
|---|---|---|
| Boot 4 拆分自动配置模块 | Redis 自动配置改名 `DataRedisAutoConfiguration` | starter-redis 用 `beforeName` 引用新全限定名 |
| Jackson 2 → Jackson 3 | `com.fasterxml` → `tools.jackson`，旧序列化器失效 | RedisTemplate 用 `RedisSerializer.json()`（Jackson 3 版通用序列化器） |
| 无 `spring-boot-starter-aop` | AOP 依赖缺失 | 直接引 `aspectjweaver` |
| 自动配置装配顺序敏感 | SBA 服务端需 Marker Bean 先于其自动配置就绪 | `@AutoConfiguration(beforeName = ...)` 显式排序 |
| JDK 要求 | Boot 4 最低 Java 17，项目用 21 | 编译命令固定 `JAVA_HOME=D:\devtools\java\jdk21` |

## 四、依赖健康度建议

- 建立依赖升级台账：Boot 4.1.0 属新线，SBA/knife4j/Redisson 的 4.x 配套版本仍在快速迭代，建议每季度核对一次 minor 版本
- 引入 `versions-maven-plugin`，定期 `display-dependency-updates` 巡检
- 空壳 starter（file/job/mq/protection/websocket）要么落地要么从 BOM 移除，避免"版本已管理 = 功能已就绪"的错觉
