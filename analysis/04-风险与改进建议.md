# 04 - 风险与改进建议

> 优先级定义：**P0** = 功能性/安全性阻断，需立即处理；**P1** = 上线前必须解决；**P2** = 中期优化；**P3** = 长期演进。

## P0：功能性/安全性阻断

### P0-1｜union 模块 44 个管理端接口无细粒度权限校验 🔴

- **现状**：`zhush-module-union/controller/admin/` 下 44 个 Controller，**0 处 `@SaCheckPermission`**；而对照的 system 模块 8 个 Controller 有 38 处。union 接口目前仅受 Sa-Token 登录态保护（`/admin/**` 前缀拦截），任何已登录管理员都能操作全部联盟业务（佣金调整、审核配置、账号流水等）。
- **风险**：横向越权。佣金/资金类接口（`UnionCommissionAdjustment`、`UnionAccountTransaction`）尤其敏感。
- **建议**：按 system 模块范式补 `@SaCheckPermission(type = CommonConstant.TYPE, value = "union:xxx:yyy")`，并在 `01_admin_rbac.sql` 补菜单/权限点数据；资金类接口额外叠加数据权限或二次校验。

### P0-2｜union 模块未接入 zhush-server，处于"编译孤岛" 🔴

- **现状**：`zhush-server/pom.xml` 只依赖 system + member，**未依赖 `zhush-module-union`**。309 个文件/16,708 行代码虽在 reactor 内可编译（本次分析已验证编译通过），但不会进入最终 jar，`/admin/union/**` 接口运行时不存在。
- **附带发现**：全量 reactor 构建此前已被破坏——`starter-file` 引用的 `x-file-storage-spring` 在 BOM 缺版本管理导致构建失败，**本次分析已修复**（补 `x-file-storage.version=2.3.0` + dependencyManagement 条目）。说明 union/file 相关模块长期未参与实际构建验证。
- **建议**：确认 union 是否应随主服务发布；若是，在 `zhush-server/pom.xml` 加依赖并跑一次真实启动验证；若独立部署，需为其建独立 server 模块。

## P1：上线前必须解决

### P1-1｜多环境配置严重滞后

- `application-prod/test/docker/my.yaml` 停留在早期版本：无 Redis 配置（Sa-Token 会话依赖 Redis，缺失会导致生产启动后登录功能异常或走默认 localhost）、无 ES/监控/CORS/搜索配置块；prod 仍保留 slave 从库占位配置（dev 已删除）。
- **建议**：以 dev 为模板同步 4 套 profile，生产值走环境变量/Jasypt。

### P1-2｜敏感信息明文 + 生产暴露 Druid 控制台

- dev 主库密码、Druid 控制台账号 `admin/your_password` 明文；**prod 也开启了 `stat-view-servlet` 且 `allow` 白名单为空**（任意 IP 可访问）。
- **建议**：启用 BOM 已托管的 Jasypt（`jasypt-spring-boot-starter`）加密 yaml 敏感项；生产 Druid 控制台要么关闭要么限白名单 + 强口令。

### P1-3｜5 个空壳 starter 仍无实现

- file（仅 pom）/job/mq/protection/websocket 均 0 行 Java，但已被 BOM 纳管、可能被业务误引。其中 **protection（限流）** 是开放 API（OAuth2）场景的刚需。
- **建议**：优先落地 protection（Redisson `RRateLimiter`，已有分布式限流设计沉淀）与 file（x-file-storage 依赖已就位）；暂不实现的在 pom 描述标注"未实现"。

## P2：中期优化

| # | 事项 | 建议 |
|---|---|---|
| P2-1 | union 无数据权限接入 | 佣金/流水类查询按 `@DataPermission` 接入行级过滤（能力已就绪） |
| P2-2 | union 代码为脚手架风格，注释模板不统一（`@ClassName/@Description/@Date` vs 项目标准 Javadoc） | 纳入代码规范检查，增量代码遵循项目注释规范 |
| P2-3 | SQL 脚本 `union.sql` 与 `zhush_union.sql` 两份并存（1319/1634 行） | 核对差异收敛为一份，避免初始化歧义 |
| P2-4 | 根目录散落 3 份历史架构建议 + 修复报告，与 docs/、analysis/ 并存 | 历史文档归档至 `docs/archive/`，保持根目录整洁 |
| P2-5 | 无任何自动化测试（test 目录仅占位） | 优先为权限/数据权限/佣金计算补单测与接口测试 |

## P3：长期演进

- 模块数量与体量增长后，可评估引入 **Spring Modulith** 做模块边界校验与模块间事件解耦
- union 若持续膨胀（当前已占全项目 58% 代码量），建议优先拆为独立部署单元
- Boot 4 生态仍在快速演进，建立 SBA/Knife4j/Redisson 等配套版本的季度巡检机制
