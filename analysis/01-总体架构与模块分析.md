## 二、分层与装配机制

| 层 | 机制 | 说明 |
|---|---|---|
| BOM | `zhush-dependencies` import `spring-boot-dependencies:4.1.0` 等 | 全部三方版本集中；`flatten-maven-plugin` + `${revision}` 统一发版 |
| 框架层 | `AutoConfiguration.imports` 自动装配 | 每个 starter 自带开关属性（如 `zhush.monitor.enabled`），关闭时零装配零开销 |
| 业务层 | 包扫描 `com.zhush` | 启动类 `scanBasePackages = "com.zhush"`；`@MapperScan(basePackages = "com.zhush", annotationClass = Mapper.class)` |
| 聚合层 | `zhush-server` 仅聚合 + 配置文件 | 5 套 profile（dev/test/prod/docker/my），logback 带 SkyWalking TID |

业务模块间**零横向依赖**（system/member/union 平级），公共能力全部下沉 starter，符合模块化单体（modular monolith）最佳实践，未来可按模块拆分微服务。

## 四、运行时关键链路

1. **认证**：Sa-Token 拦截器仅校验 `/admin/**`、`/member/**` 登录态；`/doc.html`、`/v3/api-docs/**` 等白名单放行；token 存储于 Redis（sa-token-redis-template）
2. **授权**：`@SaCheckPermission(type=TYPE, value="system:xxx:yyy")` 细粒度校验；超管 `super_admin` 全量放行
3. **数据权限**：`DataScopeProvider` SPI 由 system 模块 `AdminDataScopeProvider` 实现（角色 dataScope 1-5 → DataScope，60s 本地缓存）；starter 侧 MyBatis 拦截器改写 SQL
4. **多数据源**：Druid + MyBatis-Flex，`SysDatasource` 表驱动动态注册/切换
5. **可观测**：actuator + SBA（`/monitor`，默认关）+ SkyWalking agent 外挂（日志 `%tid`）

## 五、架构亮点与隐患

**亮点**
- starter 全部带启停开关，默认关闭 → 引入依赖不产生运行期负担
- 双账号体系（StpAdminUtil / StpMemberUtil）隔离管理端与会员端
- 数据权限以 SPI 解耦：框架不知道业务，业务实现 Provider 即可生效
- 统一 `Result<T>` 响应契约 + 全局异常处理 + 操作日志注解化

**隐患**
- union 模块体量为 system 的 4 倍，但**未被 zhush-server 依赖**，处于"编译孤岛"（详见 04 报告 P0-2）
- 5 个空壳 starter 已被 BOM 纳管，存在被业务误引而"以为有功能"的风险
- 单体聚合所有模块，启动依赖全部外部资源（MySQL/Redis/ES 按需），本地开发门槛较高
